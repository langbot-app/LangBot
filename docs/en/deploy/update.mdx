## Using the one-line install (lbctl)

```bash
lbctl upgrade --yes
```

This backs up your data, upgrades to the latest stable release and restarts LangBot. If the upgrade fails, native deployments are restored automatically and Docker deployments keep the backup for recovery. If you are already on the latest version, lbctl only tells you so and changes nothing.

- Preview the plan: `lbctl upgrade --dry-run`
- Upgrade to a specific release: `lbctl upgrade --version v4.11.8 --yes`
- Update lbctl itself: `lbctl update`, or run the one-line installer again

See [Manage LangBot with lbctl](/en/deploy/lbctl#upgrade-langbot) for details.

## Using Package Manager (uvx)

Please execute in the directory you deployed LangBot again:

```bash
uvx langbot@latest
```

This command will download and start the latest version of LangBot.

## Using Docker (or one-click deployment based on Docker)

<Tip>
Deployments started with `docker compose` can be [brought under lbctl](/en/deploy/lbctl#bring-an-existing-docker-compose-deployment-under-lbctl). After that, `lbctl upgrade --yes` is all you need, and your data is backed up before every upgrade. The steps below are the manual way without lbctl.
</Tip>

Please execute in the directory you cloned LangBot:

```bash
git pull
```

Please execute in the `docker/` directory:

```bash
docker compose up --force-recreate --pull always -d
```

This command will pull the latest LangBot image and rebuild the container.

<Info>
4.3.0 version changed the content and location of the `docker-compose.yaml` file, if you updated from a previous version, please [redploy according to the documentation](/en/deploy/langbot/docker).
</Info>

## Manual Deployment

Download the latest release's `langbot-<version>-all.zip` from the Assets section on the [Releases](https://github.com/langbot-app/LangBot/releases) page, extract it to the original deployment directory, and restart.

## Upgrade Notes (Message Policy, System Commands & Chat Rename)

If you are upgrading from 4.11 or earlier (with "Pipelines" and legacy global command config), migrations preserve existing behavior automatically. Review these changes after upgrading:

- **"Pipeline" renamed to "Chat"**: User-facing labels in WebUI and docs now say **Chat** instead of Pipeline; stored data, routes, and underlying API/CLI identifiers stay compatible.
- **Message policy moved from Chats to bots**: Trigger (group response rules, blacklist/whitelist, ignore rules, message aggregation), safety (content filter, rate limit), and general output settings now live under each bot's **Event routing → Message policy** and apply to Chats, Agents, and plugin commands alike. After upgrading, existing bots start with a neutral bot default (block nothing, change nothing) and copy each routed pipeline's former settings as a route override so behavior stays unchanged.
- **Plugins are enabled on bots**: Enable plugins under the bot's **Event routing → Plugins & commands** tab to control which plugins run commands and chat event hooks (formerly EventListener). The plugin list inside a Chat now only governs which tools the AI can invoke. Migrations carry over plugin selections from routed pipelines and include command-bound plugins.
- **Built-in system commands replace `EssentialCommands`**: 12 built-in system commands (`/help`, `/new`/`/reset`, `/stop`, `/retry`, `/undo`, `/whoami`, `/status`, `/usage`, `/model`, `/tools`, `/plugins`, `/version`) are built in and take precedence over same-named plugin commands; the default prefix for new bots is `/`. If your instance previously configured `!` or `！` in `data/config.yaml`, use the Upgrade Check Assistant to keep those prefixes or customize per bot.
- **Configure bot admins in Session Monitoring**: The legacy `command_settings.admins` configuration is retired. Admin-only system and plugin commands now check the bot's admin list configured in **Sessions** (use `/whoami` to inspect sender IDs such as `person_10001`). An empty admin list grants nobody admin access.
- **Upgrade Check Assistant**: After upgrading, the **Upgrade checks** banner at the top of the Bots and Chats pages lists prefix changes, colliding plugin commands or an installed `EssentialCommands` plugin, bots missing admins, newly enabled command plugins, equivalent route overrides that can be promoted to the bot default, and moved Chat settings—with one-click actions and confirmations.
