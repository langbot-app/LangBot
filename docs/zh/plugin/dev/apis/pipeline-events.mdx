---
title: "消息生命周期事件和 API"
---

LangBot 插件可通过[组件：事件监听器](/zh/plugin/dev/components/event-listener)监听机器人收到消息后的各个阶段（消息生命周期）。这些钩子挂在**机器人**上，不论消息最终交给聊天、Agent 还是插件命令处理，都按同一套规则触发。

<Info>
本页原名「流水线事件」。事件类名和字段没有变化，旧插件无需修改。
</Info>

## 插件在哪里启用

插件在**机器人**上启用：机器人的「事件路由 → 插件」页签与聊天原来的插件设置一样，可以「启用所有插件」，也可以手动选择插件；单条路由可以覆盖机器人的设置。启用一个插件，就同时启用了它的全部命令和事件监听器；未启用的插件收不到这个机器人的任何事件，命令也不会匹配。

聊天里的插件列表现在只决定 AI 可以调用哪些插件工具，不再决定监听器是否触发。

同一事件按机器人插件列表中的顺序分发给插件；没有注册该事件的插件会被跳过。

## 消息生命周期

机器人收到一条消息（`message.received`）后按以下顺序处理：

```text
预选路由（只计算命中哪条路由，不执行）
→ *MessageReceived                （拦截则整条消息结束）
→ 是插件命令？
    是 → 入口策略（群响应规则、黑白名单、限速、内容过滤）
         → *CommandSent           （拦截则不执行命令）
         → 执行命令 → 出口策略（长文本、延迟、@、引用）
    否 → 入口策略
         → 聊天：PromptPreProcessing → *NormalMessageReceived → AI → NormalMessageResponded
         → Agent：*NormalMessageReceived → Agent → NormalMessageResponded
         → 出口策略
```

- 每条消息只创建一个查询（Query）。钩子、命令和后续处理器共用它，所以在任何钩子和命令里都能使用 `reply()`、`get_bot_uuid()` 和查询变量。
- `*MessageReceived` 在群响应规则等入口策略**之前**触发，插件能看到群里没有 @ 机器人的消息；路由规则判定丢弃的消息也会触发它。
- 入口和出口策略来自机器人的「消息策略」，详见[机器人](/zh/usage/platforms/readme)。

## 每个钩子在哪些处理器上生效

| 事件 | 聊天 | Agent | 插件命令 |
| --- | --- | --- | --- |
| `*MessageReceived` | ✓ | ✓ | ✓ |
| `*NormalMessageReceived` | ✓ | ✓ | — |
| `*CommandSent` | — | — | ✓ |
| `NormalMessageResponded` | ✓ | ✓（流式回复只能旁观） | — |
| `PromptPreProcessing` | ✓ | — | — |
| 平台事件通知（见下文） | ✓ | ✓ | ✓ |

已知限制：

- `PromptPreProcessing` 只在聊天中触发，Agent 不会触发。
- 流式回复在发送过程中已经发给用户，`NormalMessageResponded` 只能收到通知，不能改写或替换已发出的内容。非流式回复可以改写。
- 插件处理器（事件路由直接交给插件处理的事件）不经过入口拦截，但它的回复会经过同一个出口策略。

机器人的「插件」页签会按当前路由的处理器给每个钩子打上「生效 / 不生效」标签。

## 可监听的事件列表

某些事件具有`可设置的属性`，这些属性可以被插件代码修改，并在之后被用在 LangBot 后续的处理中。

### \*MessageReceived

机器人收到群聊或私聊的任何消息时触发，早于群响应规则和命令匹配。拦截（`prevent_default()`）后这条消息不再继续处理；插件改写的 `message_chain` 会传给后续步骤。

```python
class PersonMessageReceived(BaseEventModel):
    """收到任何私聊消息时"""

    event_name: str = "PersonMessageReceived"

    launcher_type: str
    """发起对象类型(person)"""

    launcher_id: typing.Union[int, str]
    """发送者ID"""

    sender_id: typing.Union[int, str]
    """发送者ID，私聊情况下与 launcher_id 相同"""

    message_event: platform_events.PersonMessage
    """原消息事件对象。包含发送者的信息。"""

    message_chain: platform_message.MessageChain = pydantic.Field(
        serialization_alias="message_chain"
    )
    """消息链"""


class GroupMessageReceived(BaseEventModel):
    """收到任何群聊消息时"""

    event_name: str = "GroupMessageReceived"

    launcher_type: str
    """发起对象类型(group)"""

    launcher_id: typing.Union[int, str]
    """群号"""

    sender_id: typing.Union[int, str]
    """发送者ID"""

    message_event: platform_events.GroupMessage
    """原消息事件对象。包含群聊和发送者的信息。"""

    message_chain: platform_message.MessageChain = pydantic.Field(
        serialization_alias="message_chain"
    )
    """消息链"""
```

### \*NormalMessageReceived

消息通过入口策略、确定交给聊天或 Agent 处理（不是命令）时触发。插件拦截并回复则替代 AI 回复；改写输入则 AI 收到改写后的内容。

```python
class PersonNormalMessageReceived(BaseEventModel):
    """判断为应该处理的私聊普通消息时触发"""

    event_name: str = "PersonNormalMessageReceived"

    launcher_type: str
    """发起对象类型(person)"""

    launcher_id: typing.Union[int, str]
    """发起对象ID"""

    sender_id: typing.Union[int, str]
    """发送者ID，私聊情况下与 launcher_id 相同"""

    text_message: str
    """消息文本"""

    message_event: platform_events.PersonMessage
    """原消息事件对象。包含发送者的信息。"""

    message_chain: platform_message.MessageChain = pydantic.Field(
        serialization_alias="message_chain"
    )
    """消息链"""

    # ========== 可设置的属性 ==========

    user_message_alter: typing.Optional[provider_message.ContentElement] = None
    """修改后的消息文本，langbot_plugin.api.entities.builtin.provider.message.ContentElement 类型"""

    reply_message_chain: typing.Optional[platform_message.MessageChain] = None
    """直接回复消息链，仅在阻止默认行为时生效"""


class GroupNormalMessageReceived(BaseEventModel):
    """判断为应该处理的群聊普通消息时触发"""

    event_name: str = "GroupNormalMessageReceived"

    """发起对象类型(group)"""

    """消息链"""

    """修改后的消息文本，langbot_plugin.api.entities.builtin.provider.message.ContentElement 类型"""

    """直接回复消息链，仅在阻止默认行为时生效"""
```

### \*CommandSent

插件命令通过入口策略之后、执行之前触发。拦截则不执行命令，可通过 `reply_message_chain` 给出替代回复。命令本身请使用[组件：命令](/zh/plugin/dev/components/command)实现。

```python
class PersonCommandSent(BaseEventModel):
    """判断为应该处理的私聊命令时触发"""

    event_name: str = "PersonCommandSent"

    launcher_type: str
    """发起对象类型(person)"""

    launcher_id: typing.Union[int, str]
    """发起对象ID"""

    sender_id: typing.Union[int, str]
    """发送者ID，私聊情况下与 launcher_id 相同"""

    command: str
    """命令文本"""

    params: list[str]
    """命令参数"""

    text_message: str
    """消息文本"""

    is_admin: bool
    """是否为管理员"""


class GroupCommandSent(BaseEventModel):
    """判断为应该处理的群聊命令时触发"""

    event_name: str = "GroupCommandSent"

    launcher_type: str
    """发起对象类型(group)"""

    launcher_id: typing.Union[int, str]
    """群号"""

    sender_id: typing.Union[int, str]
    """发送者ID"""

    command: str
    """命令文本"""

    params: list[str]
    """命令参数"""

    text_message: str
    """消息文本"""

    is_admin: bool
    """是否为管理员"""
```

### NormalMessageResponded

聊天或 Agent 产生回复后触发。非流式回复在发送前触发，可以改写或替换；流式回复只做旁观通知。

```python
class NormalMessageResponded(BaseEventModel):
    """收到对普通消息的响应时触发"""

    event_name: str = "NormalMessageResponded"

    launcher_type: str
    """发起对象类型(person)"""

    launcher_id: typing.Union[int, str]
    """发起对象ID"""

    sender_id: typing.Union[int, str]
    """发送者ID，私聊情况下与 launcher_id 相同"""

    session: provider_session.Session
    """会话对象"""

    prefix: str
    """回复消息的前缀"""

    response_text: str
    """回复消息的文本"""

    finish_reason: str
    """响应结束原因"""

    funcs_called: list[str]
    """调用的函数列表"""

    # ========== 可设置的属性 ==========

    reply_message_chain: typing.Optional[platform_message.MessageChain] = None
    """直接回复消息链，仅在阻止默认行为时生效"""
```

### PromptPreProcessing

聊天构建 LLM 上下文（prompt）时触发。Agent 不触发此事件。

```python
class PromptPreProcessing(BaseEventModel):
    """会话中的Prompt预处理时触发"""

    event_name: str = "PromptPreProcessing"

    session_name: str
    """会话名称，格式为 person_1234567890 或 group_1234567890"""

    # ========== 可设置的属性 ==========

    default_prompt: list[
        typing.Union[provider_message.Message, provider_message.MessageChunk]
    ]
    """此对话的情景预设（系统提示词），可修改，langbot_plugin.api.entities.builtin.provider.message.Message 或 langbot_plugin.api.entities.builtin.provider.message.MessageChunk 类型"""

    prompt: list[typing.Union[provider_message.Message, provider_message.MessageChunk]]
    """此对话现有消息记录，可修改，langbot_plugin.api.entities.builtin.provider.message.Message 或 langbot_plugin.api.entities.builtin.provider.message.MessageChunk 类型"""
```

注入本轮检索证据时，可向 `prompt` 或 `default_prompt` 追加 `Message(role="system", content=...)`。Host 会把 `prompt` 中新增或修改的系统消息通过 Runner 的 `get_prompt()` API 传递，排在生效的 `default_prompt` 之后，保留最终事件处理顺序，并在每一轮重新构建。Runner 在调用模型前应用上下文预算。对话历史继续通过 Runner 的历史 API 获取。提示词预处理上下文的作用域为当前运行。

事件处理后的 `_knowledge_base_uuids` 查询变量决定本次运行的自动检索范围。空列表会关闭自动检索，未设置时沿用配置中的选择。显式检索 API 继续校验运行时冻结的资源授权。记忆插件应先完成自身的查询级检索，再从自动检索范围中移除其知识库。

## 平台事件通知

以下事件在消息平台产生对应事件时通知已启用的插件，**只通知、不能拦截**，也不影响路由。`MessageReceived`（不带 Person/Group 前缀）是 `message.received` 的通用通知，在 `*MessageReceived` 之前发出。

| 事件 | 可产生该事件的平台 |
| --- | --- |
| `MessageReceived` | 全部平台 |
| `MessageDeleted` | OneBot v11、Discord、飞书、LINE、Slack、企业微信客服 |
| `MessageEdited` | Discord、Slack、Telegram |
| `MessageReactionReceived` | Discord、飞书、QQ 官方、Slack、Telegram |
| `GroupMemberJoined` / `GroupMemberLeft` / `BotInvitedToGroup` / `BotRemovedFromGroup` | Discord、飞书、LINE、OneBot v11、QQ 官方、Slack、Telegram |
| `GroupMemberBanned` | OneBot v11、Telegram |
| `BotMuted` / `BotUnmuted` | Telegram |
| `FeedbackReceived` | 钉钉、企业微信智能机器人 |
| `PlatformSpecificEventReceived` | 钉钉、KOOK、飞书、LINE、微信公众号、OneBot v11、QQ 官方、Slack、Telegram、企业微信、企业微信智能机器人、企业微信客服 |

能否收到取决于平台是否把对应事件推送给机器人。

## EventListener 上下文

事件处理函数通过 `event_context.event` 读取当前事件。`EventContext` 的完整属性和方法见[上下文 API](/zh/plugin/dev/apis/agent-run#eventlistener)。

### 阻止默认行为

调用 `event_context.prevent_default()` 后，当前事件的默认处理将停止。仅以下事件支持此操作：

<Info>
仅以下事件可阻止默认行为：

  - PersonMessageReceived
  - GroupMessageReceived
  - PersonNormalMessageReceived
  - GroupNormalMessageReceived
  - PersonCommandSent
  - GroupCommandSent
  - NormalMessageResponded
</Info>

调用 `event_context.prevent_postorder()` 可阻止后续插件继续处理当前事件。

#### 在监控中的显示

插件对消息类事件调用 `prevent_default()` 接管消息后，LangBot 的监控页会把这条消息标记为「插件处理 · 作者/插件名」，聊天或 Agent 不会再显示为处理者。插件在处理事件时发出的内容也会记入监控：

- `event_context.reply()` 发出的回复，记为这条消息的回复；发送失败会记一条 `PluginReplyError` 错误。
- `self.plugin.send_message()` 发出的消息，记为插件发送的消息；发送失败会记一条 `PluginSendError` 错误。
- `self.plugin.invoke_llm()` / `invoke_llm_stream()` 的调用，记入 LLM 调用记录。

需要插件运行时（`langbot-plugin`）支持事件来源归因，才能把插件发出的消息和 LLM 调用关联到触发它的那条消息；较旧的运行时仍会记录这些内容，但不会关联。在处理函数返回后才执行的后台任务不会关联到原消息。
