## 使用一行命令安装（lbctl）部署

```bash
lbctl upgrade --yes
```

这会备份数据、升级到最新稳定版并重新启动；升级失败时会自动恢复（原生部署）或保留备份供恢复（Docker 部署）。已是最新版本时只会提示，不会做任何改动。

- 先看升级计划：`lbctl upgrade --dry-run`
- 升级到指定版本：`lbctl upgrade --version v4.11.8 --yes`
- 升级 lbctl 本身：`lbctl update`，或重新执行一次一行命令安装脚本

详见[使用 lbctl 管理 LangBot](/zh/deploy/lbctl#升级-langbot)。

## 使用包管理器（uvx）部署

请在之前使用包管理器部署的目录下重新执行：

```bash
uvx langbot@latest
```

这将重新下载并启动最新版本的 LangBot。

## 使用 Docker（或基于 Docker 的一键部署）

<Tip>
用 `docker compose` 部署的实例可以[接入 lbctl](/zh/deploy/lbctl#已有的-docker-compose-部署接入-lbctl)，之后同样只需 `lbctl upgrade --yes`，并且升级前会自动备份数据。下面是不使用 lbctl 时的手动方式。
</Tip>

请在之前 Clone 的 LangBot 目录下执行：

```bash
git pull
```

并在 `docker/` 目录下执行：

```bash
docker compose up --force-recreate --pull always -d
```

此命令将拉取最新的 LangBot 镜像并重建容器。

<Info>
4.3.0 版本更改了 `docker/docker-compose.yaml` 文件的内容和位置，若您由之前版本更新而来，请[根据文档重新部署](/zh/deploy/langbot/docker)。
</Info>

## 手动部署

从 [Releases](https://github.com/langbot-app/LangBot/releases) 页面下载最新发行版的 Assets 下的 `langbot-<version>-all.zip`，解压到原来部署到目录重启即可。

## 升级说明（消息策略、系统命令与聊天改名）

如果你从带有「流水线」和旧全局命令配置的 4.11 及更早版本升级到当前版本，升级迁移会自动保留现有运行效果；建议在升级后对照以下变化核对配置：

- **「流水线」更名为「聊天」**：WebUI 与文档中的「流水线 / Pipeline」统一改名为**聊天 / Chat**，原有数据、路由与外部 API/CLI 标识保持兼容。
- **消息策略从聊天迁至机器人**：原属于单个聊天的触发条件（群响应规则、黑白名单、忽略规则、消息聚合）、安全（内容过滤、限速）和通用输出设置，现已迁至机器人的**事件路由 → 消息策略**，同时作用于聊天、Agent 和插件命令。升级后，已有机器人的默认策略为「不拦截、不处理」，原有指向流水线的路由会把旧流水线设置复制为路由覆盖，保证行为不变。
- **插件改在机器人上启用**：现在请在机器人的**事件路由 → 插件和命令**页签中选择启用哪些插件（同时控制该插件的命令与聊天事件钩子生效）。聊天详情页里的插件列表现在仅用于控制 AI 可调用哪些工具插件。升级时会自动合并路由指向的流水线原先启用的插件，并把绑定过命令的插件一并加入机器人启用列表。
- **内置系统命令替代 `EssentialCommands`**：LangBot 内置了 `/help`、`/new`（别名 `/reset`）、`/stop`、`/retry`、`/undo`、`/whoami`、`/status`、`/usage`、`/model`、`/tools`、`/plugins`、`/version` 共 12 个系统命令，启用后优先于同名插件命令；新机器人默认前缀为 `/`。若旧实例此前在 `data/config.yaml` 中使用 `!` 或 `！` 等命令前缀，可在升级检查助手中一键保留原有前缀。
- **在会话监控中设置机器人管理员**：原 `command_settings.admins` 已停用，系统命令和插件命令的管理员权限统一读取机器人**会话监控**中配置的管理员列表（可发送 `/whoami` 获取发送者 ID，例如 `person_10001`）。管理员列表为空时，仅管理员可用的命令无人可以执行。
- **升级检查助手**：升级后，在「机器人」与「聊天」页面顶部会显示**升级检查**横幅，汇总前缀变化、与系统命令重名的插件或已安装的 `EssentialCommands`、缺少管理员、迁移时新启用的命令插件、可简化提升为机器人默认的等价路由覆盖，以及原聊天设置迁移情况。你可以直接点击一键操作处理或确认。
