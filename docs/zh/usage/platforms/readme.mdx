机器人用于从消息平台接收消息事件，并按「事件路由」交给聊天、Agent 或插件处理器处理。

## 事件路由、插件与消息策略

机器人详情页的「事件路由」有三个页签：

- **路由规则**：决定每类事件交给哪个处理器。收到的消息可以交给聊天（原「流水线」）、Agent 或插件处理器；可以按条件设置多条路由，都不匹配时使用默认路由。
- **插件和命令**：选择在这个机器人上启用的插件（「启用所有插件」或手动选择），并配置内置[系统命令](/zh/deploy/system-commands)与插件命令的启用、前缀（默认 `/`）和权限（`everyone` / `admins`）；启用的系统命令优先于同名插件命令。启用一个插件会同时启用它的命令和聊天事件钩子（原 EventListener）。单条路由可单独覆盖插件选择；每个插件旁会标出它的钩子在当前路由的处理器上是否生效，例如 `PromptPreProcessing` 只在聊天中生效。
- **消息策略**：原来在流水线里的「触发条件、安全、通用输出」设置，现在放在机器人上，对聊天、Agent 和插件命令都生效。机器人有一份默认策略，单条路由可以覆盖。

消息策略包括：

| 分类 | 设置 |
| --- | --- |
| 触发条件 | 群响应规则（@、前缀、正则、随机）、访问控制（黑名单 / 白名单）、忽略规则、消息聚合、合并引用消息 |
| 安全 | 内容过滤、限速 |
| 通用输出 | 长文本处理、强制延迟、@发送者、引用原消息、异常处理方式与各类提示语 |

说明：

- 策略只对「收到消息」（`message.received`）生效，其他平台事件不受影响。
- 插件命令先于路由规则匹配，但沿用这条消息本来会命中的路由的策略；没有命中路由时使用机器人默认策略。
- Agent 的流式回复只应用延迟、@发送者和引用，长文本处理不适用；插件主动发送的消息（`send_message`）不受策略影响。
- 聊天的调试对话不经过机器人，使用不拦截、不处理的中性策略，因此预览不到长文本、@ 等效果。
- 从旧版本升级时，已有机器人的默认策略为「不拦截、不处理」，每条指向流水线的路由会把原流水线的这些设置复制为路由覆盖，行为保持不变。

![arch](/images/zh/deploy/bots/arch.png)

运行 `lbctl bot get <bot>` 查看路由 ID，再用 `lbctl bot routes bind <bot> --binding <id> --agent <agent> --dry-run` 预览。确认后用 `--yes` 应用。绑定聊天时可用 `--pipeline`。若有人并发修改了路由，Core 返回冲突，此时可重新读取并核对。

**按群路由**：要让某个群使用指定的聊天或 Agent，打开机器人的**会话监控**，选中该群的会话，标题下方会显示完整的**群 ID**（可复制）。点击**为此群配置路由**，LangBot 会在事件路由最上方添加一条“会话类型 = 群聊、会话 ID = 该群 ID”的规则，选择处理目标后保存即可；其他群继续走下方的规则。执行详情抽屉中同样会显示群 ID 和该入口。

## 会话监控与升级检查

- **会话监控**：会话列表与执行记录支持按处理方式筛选，并用徽标区分 4 类结果：**AI 处理**、**命令**（标注系统命令、插件命令及「命令被拒」）、**插件**（事件处理器 / 插件拦截）与**策略拦截**（显示触发的规则名及来自机器人默认还是路由覆盖）。点开执行详情可查看「消息策略」四阶段时间线（**准入** → **生命周期钩子** → **处理器** → **输出处理**）。在「路由规则」页签中，每条路由还会展示近 24 小时的 AI / 命令 / 插件 / 拦截计数。
- **机器人管理员**：在机器人的**会话监控**中可将指定发送者（可通过 `/whoami` 查看）设为管理员；管理员名单为空时，仅管理员可用的系统命令和插件命令均无法执行。
- **升级检查**：从旧版本升级后，机器人列表、机器人详情和聊天详情页顶部会显示**升级检查**横幅，提示命令前缀变更、与系统命令重名或已安装 `EssentialCommands`、缺少管理员、迁移时启用的命令插件、等价路由覆盖简化以及原聊天设置迁移情况，并支持一键调整或确认。

<Tip>
**不想折腾公网 IP 和域名？** 企业微信、微信公众号、QQ 官方机器人、飞书、钉钉、Slack、LINE 等平台需要配置 Webhook 回调地址，这意味着你需要公网服务器、域名和 HTTPS 证书。[LangBot Cloud](https://space.langbot.app/cloud) 自带域名解析和 HTTPS，注册即可直接使用，省去繁琐的网络配置。
</Tip>
