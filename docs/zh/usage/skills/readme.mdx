---
title: "技能 (Skills)"
description: "在 LangBot 中使用技能（Skills），按需加载专业知识，扩展 AI Agent 而不撑爆上下文。"
---

Skill 是一个**按需激活**的指令包：用户描述匹配时，Agent 调用 `activate` 工具把这个技能的指令拉进上下文，然后按指令完成任务。未激活的技能不占用上下文。

适合给 Agent 加一段**专业流程、模板或脚本**——比如"分析 Python 项目"、"PDF 表单填充"、"代码评审"——而不必每个对话都把指令塞进 System Prompt。

## 与插件、MCP 的区别

| 你想做的事 | 用这个 |
|------------|--------|
| 按需触发的一段工作流（可带脚本、模板） | Skill |
| 接入已有的 MCP 工具服务 | MCP Server |
| 长期能力，需要配置页、事件、知识库 | 插件 |

详见[运行时与扩展关系](../sandbox/runtime-relationships)。

## 安装技能

<Note>
技能的管理、激活和只读资源访问由 Core 提供，不要求 Box。执行脚本、操作沙箱草稿和 `register_skill` 需要可用的 Box。详见[沙箱配置](../sandbox/config)。
</Note>

### 从 LangBot Space（首选）

[LangBot Space](https://space.langbot.app) 是 LangBot 的官方市场，已上架多种技能。在 WebUI 的 Skills 页面浏览并一键安装，无需自己编写 `SKILL.md` 或准备资源文件。

适合大多数场景。需要自定义流程再走下面的方式。

### 自己创建技能

**WebUI** — Skills 页面新建、上传 zip 包、从 GitHub 导入。

**沙箱 + `register_skill`**：
1. 在沙箱 `/workspace` 下准备好目录和 `SKILL.md`
2. 让 Agent 调用 `register_skill(path="/workspace/my-skill")`

两种方式都会发布到 Core 管理的技能仓库。

### 数据库存储（显式启用）

默认仍为本地模式；数据库模式需显式启用，使用独立索引。旧技能、上传附件和媒体不会自动导入，原文件保留；已有数据的部署须先迁移再切换，旧链接不会自动回读原后端。此模式将注册信息、不可变版本包和持久附件内容默认存入数据库，对象存储可选。此模式需要配套的 Core 和 SDK；源码开发请先按[运行时开发说明](../../develop/plugin-runtime)安装仓库中的 SDK。多个 Core 应连接同一个外部 PostgreSQL，并使用一致的逻辑实例标识和鉴权配置。修改 `data/config.yaml` 后重启 Core：

```yaml
skills:
    persistence: database
    root: './data/skills'
storage:
    use: persistent
    content:
        backend: database
```

使用配套的 Core 和 Box Runtime 时，可显式设置 `box.file_transfer_mode: network`：Core 按运行固定版本传输技能包，Box 校验后缓存并只读挂载；Core 与 Box 无需共享技能或工作目录。数据库模式下，激活和执行不再创建 `skills.root/.database-cache`，资源读取只使用请求期间的临时目录。`register_skill` 通过网络取回沙箱草稿，校验后一次发布；新版本不会改变已开始运行的版本。运行结束清理该运行的输入、输出和临时快照，草稿保留到 Box 会话结束。Box 会话过期或删除后，其工作目录也会删除；需要保留的文件请先导出。默认仍为 `legacy`，旧共享挂载和缓存行为保留，不自动迁移数据。源码开发需同时安装仓库 SDK，旧 Runtime 会拒绝网络工作区配置。

使用对象存储时，在 `storage.content.backends.<名称>` 下配置 `type: s3`、`endpoint_url`、`bucket`、`region`、`access_key_id` 和 `secret_access_key`，再将 `storage.content.backend` 设置为该名称。保留历史名称及其 endpoint/bucket/region；切换新写入后端不会移动历史内容，删除或改指向旧配置会使相应内容无法读取。修改凭据后重启 Core。

数据库模式的版本包上限为 64 MiB。网络模式的 `register_skill` 草稿使用未压缩 ZIP，上限为 20 MiB、512 个条目、单文件 16 MiB、目录深度 16；较低的 Box 文件传输配置限额仍会生效，超限会保留原草稿。并发更新会拒绝冲突覆盖，已激活任务继续使用固定版本。


## 在流水线启用

技能装好之后，还要在流水线扩展配置里决定 Agent 能看到哪些：

- 开启"启用所有技能"，或
- 只绑定指定技能

绑定只影响 `<available_skills>` 列表（即 Agent 能从哪些技能里挑），完整指令永远等 `activate` 被调用后才注入。

## 编写 SKILL.md

技能就是一个目录加一个 `SKILL.md`。frontmatter 写元数据，正文是 Agent 激活后会收到的指令：

```markdown
---
name: code-reviewer
display_name: 代码评审助手
description: 审查代码并给出改进建议；用户提到 review、评审、代码改进时触发
---

## 执行步骤

1. 用 `read` 浏览相关文件
2. 检查可读性、潜在 bug、安全问题
3. 给出按优先级排序的改进建议
```

LangBot 当前读取以下三个字段：

| 字段 | 必需 | 说明 |
|------|------|------|
| `name` | 创建/注册时 | 唯一标识，1–64 字符 |
| `description` | 强烈建议 | Agent 用它判断何时激活——越具体越能选中 |
| `display_name` | 否 | UI 显示名 |

`description` 是 Agent 挑技能的唯一依据，要写清楚**功能、适用场景、可能的触发关键词**。

完整规范见 [agentskills.io](https://agentskills.io/home)。其它字段（`license`、`metadata` 等）可保留供未来兼容，当前不会被读取。

**带资源的技能**在 `SKILL.md` 同级放 `scripts/`、`templates/` 等目录，执行时使用激活结果返回的固定版本路径。

### Agent 可用的工具

| 工具 | 用途 |
|------|------|
| `activate` | Agent 判断匹配时自动调用，把 SKILL.md 拉进上下文 |
| `register_skill` | 把沙箱里准备好的目录注册为新技能 |

## 分享到 LangBot Space

在技能详情页点击「分享到 Space」，可以把当前版本的 Skill 包投稿到扩展市场。弹窗会列出将要提交的文件；文件中包含 API Key、令牌等凭据时无法提交。投稿会以你的 LangBot Space 创作者身份发布，审核会检查脚本与外部请求，通过后公开。同一作者再次分享同名 Skill 会发布为新版本。

## 常见问题

| 现象 | 检查项 |
|------|--------|
| 技能列表为空 | Workspace、技能绑定、`skills.persistence` 和 `skills.root` |
| Agent 不激活技能 | `description` 是否具体、流水线是否绑定、模型是否支持函数调用 |
| 激活后找不到文件 | 文件需在 Skill 包内，使用激活结果返回的版本路径 |
| `register_skill` 报错 | 路径必须在 `/workspace` 下，目录或两层内子目录需含 `SKILL.md` |

<Note>
自动激活需要 Runner 支持技能和工具调用，脚本执行需要 Box。外部运行器（Dify、n8n、Langflow、Coze 等）请使用各自平台支持的机制。
</Note>
