---
title: "工作流"
description: "按固定步骤处理消息、命令、定时任务和平台事件，不用写插件。"
---

工作流是和聊天、Agent、插件处理器并列的一种处理器：收到消息（或命令、定时、平台事件、Webhook）后，按你排好的步骤依次执行，比如判断意图、调用模型或接口、记住信息，然后回复。很多原来要写插件才能做的事，例如天气查询、每日运势、关键词提醒、定时推送、入群欢迎、签到排行，都可以用工作流完成。

## 创建工作流

1. 打开**处理器**，点击**创建**，选择**工作流**。
2. 选一个模板开始：**空白**、**按意图分流**、**关键词回复**、**查询接口后回复**。
3. 进入编辑页：左边是**试运行**，右边是**步骤编排**。

## 编排步骤

- 步骤从上到下自动排列，每个工作流都从**开始**步骤出发。
- 在任意步骤下方点 **+** 添加下一步。插在两个步骤之间时，原来的后续步骤会接在新步骤下面。
- **问题分类**和**条件判断**会按分类或情况自动展开分支，都不符合时走**其他**分支。
- 点击步骤，在右侧编辑它的设置。需要用到前面步骤的结果时，点输入框右上角的 **{ }**，从列表里选择，例如「开始 · 文本」「查询订单 · 响应 JSON」。灰色小字是上次试运行时的值。
- 有问题的步骤会标红，例如没选模型或引用了不存在的结果。保存后，页面标题旁会显示问题数量。

## 触发方式

点击**开始**步骤设置触发方式，可以同时添加多种：

| 触发方式 | 说明 |
| --- | --- |
| 收到消息 | 在机器人的**事件路由**里把 `message.received` 指向这个工作流。机器人的访问规则、限流和输出设置照常生效。 |
| 命令 | 例如 `/天气 北京`。可设置别名、参数（按空格切分，最后一个参数取剩余全部）、是否仅管理员可用、在哪些机器人上可用。命令会和系统命令、插件命令一起出现在 `/help` 中；重名时系统命令优先，其次是插件命令。参数缺失时，机器人会回复用法提示。 |
| 定时 | 每天、每周、每隔 N 分钟，或自定义 cron（按工作流时区计算）。选择用哪个机器人发、发到哪些群或人；每个会话各运行一次，**回复消息**会发到该会话。 |
| 平台事件 | 例如新人入群、成员退群、消息撤回、好友申请。还需要在机器人的事件路由里把这些事件指向这个工作流。 |
| Webhook | 外部系统向生成的地址 `POST` 一个 JSON 对象即可触发，在「开始 · 请求内容」里读取。地址里带有密钥，请妥善保管。 |

## 步骤

| 分组 | 步骤 | 用途 |
| --- | --- | --- |
| AI | 模型回复 | 按提示词生成文字，可带上最近 10 轮对话，也可读取消息里的图片 |
| AI | 问题分类 | 按用户意图分支 |
| AI | 提取信息 | 从消息里取出订单号、城市等字段 |
| AI | 知识库检索 | 从知识库找相关片段 |
| AI | 文字转语音 / 语音转文字 | 生成语音，或识别用户发来的语音 |
| 判断与数据 | 条件判断 | 按规则（包含、等于、大于、正则等）分支，不用写表达式 |
| 判断与数据 | 随机 | 随机挑一个、随机数字，或「同一个人同一天结果相同」（适合今日运势） |
| 判断与数据 | 记住信息 | 存值、计数加 1、追加到列表、删除。范围可以是本次运行、每个用户、每个群或整个工作流，适合签到、次数限制和排行榜 |
| 判断与数据 | 读取聊天记录 | 读取这个会话或这个群最近的消息，常用于总结 |
| 判断与数据 | 代码 | 在沙箱里运行 Python（最长 10 秒），需要实例启用 Box |
| 动作 | 回复消息 | 回复发消息的人，可附带图片或语音。引用和 @ 跟随机器人的消息策略 |
| 动作 | 发到其他会话 | 通过当前或指定机器人发给某个群或人 |
| 动作 | 调用接口 | 请求 HTTP 服务，得到状态码、响应内容和 JSON。内网地址会被拒绝 |
| 动作 | 平台操作 | 禁言、解除禁言、移出群、撤回消息、改群名、查询成员等；平台不支持时这一步会失败 |
| 动作 | 交给处理器 | 把消息转交给聊天、Agent 或另一个工作流，由它接着处理并回复；之后不能再接步骤 |

**模型回复**、**调用接口**和**平台操作**可以在「更多设置」里选择失败时继续，结果留空。

## 试运行与运行记录

- **试运行**会使用编排区当前的内容，包括未保存的修改。回复只显示在试运行区域，不会发给任何机器人。走过的步骤变绿并显示耗时，没走到的分支变灰；点击步骤可以查看它的输入和输出。
- 输入 `/命令 参数` 可以试运行命令触发。
- **运行记录**页签按时间列出每次运行，可以查看每一步的输入、输出和错误。消息触发的运行也会出现在仪表盘的执行记录里。

## 进阶：模板写法

插入的变量形如 `{{ 步骤ID.结果 }}`。记住的信息写作 `{{ memory.user.名称 }}`，其中范围可以是 `run`、`user`、`group`、`workflow`。模板基于沙箱化的 Jinja，可以用 `{% for item in http_1.json.items %}…{% endfor %}` 排列列表，也可以使用 `length`、`join`、`default`、`truncate`、`date`、`random`、`json` 等过滤器。

## 限制

- 步骤是一棵树：每个步骤只能有一个上一步，分支之间不会汇合，也没有循环。
- 一次运行最长 300 秒。
- **代码**步骤需要实例启用 Box 沙箱。
