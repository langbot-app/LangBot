Command コンポーネントは、コマンドプレフィックス（ボットの「プラグイン」タブにある「プラグインコマンド」欄で設定、既定は `/`）で始まるユーザーメッセージによってトリガーされます。コマンドは**ボット**に属し、ボット（またはメッセージが一致するルート）で有効なプラグインのコマンドだけが一致します。コマンドをトリガーする例を次に示します:

<img width="600" src="/images/zh/plugin/dev/components/command_use.png" />

## Commandコンポーネントの追加

1つのプラグインには任意の数のコマンドを含めることができます。プラグインディレクトリでコマンド`lbp comp Command`を実行し、プロンプトに従ってコマンド設定を入力します。

```bash
➜  HelloPlugin > lbp comp Command
Generating component Command...
Command name: info
Command description: Show information of the query
Component Command generated successfully.
組件 Command 生成成功。
```

これにより、`components/commands/`ディレクトリに`info.yaml`と`info.py`ファイルが生成されます。`.yaml`ファイルは`!info`コマンドの基本情報を定義し、`.py`ファイルはコマンドハンドラです:

```bash
➜  HelloPlugin > tree
...
├── components
│   ├── __init__.py
│   ├── commands
│   │   ├── __init__.py
│   │   ├── info.py
│   │   └── info.yaml
...
```

## マニフェストファイル: Commandコンポーネント

```yaml
apiVersion: v1  # 変更しないでください
kind: Command  # 変更しないでください
metadata:
  name: info  # コマンド名、ユーザーは!infoでこのコマンドをトリガーします
  label:  # コマンド表示名、LangBot UIに表示、多言語対応
    en_US: Info
    zh_Hans: Info
  description:  # コマンド説明、LangBot UIに表示、多言語対応。オプション。
    en_US: 'Show information of the query'
    zh_Hans: '発送此次消息的詳細信息'
spec:
execution:
  python:
    path: info.py  # コマンドハンドラ、変更しないでください
    attr: Info  # コマンドハンドラクラス名、info.pyのクラス名と一致
```

## コマンドの一致と適用

- コマンドは `message.received` にのみ適用され、「プレフィックス + 登録済みコマンド名」で**ルートのルールより先に**照合されます。一致したコマンドはそのまま実行され、チャット、Agent、プラグイン処理には渡されません。
- コマンドには、そのメッセージが本来一致するルートのメッセージポリシー（グループ応答ルール、アクセス制御、レート制限、コンテンツフィルタ、長文、@メンション、引用）が適用されます。一致するルートがない場合はボットの既定ポリシーが使われます。
- コマンドメッセージも `*MessageReceived` を発火します。受付後・実行前に `*CommandSent` が発火し、プラグインでインターセプトできます。[メッセージライフサイクルイベント](/ja/plugin/dev/apis/pipeline-events)を参照してください。
- コマンド実行中も `context.reply()` や `get_bot_uuid()` などクエリに依存する API を使えます。
- コマンドはメッセージ集約の対象外です。`/stop` は引き続き進行中の AI 返信を停止できます。

## コマンド設定

コマンドはマニフェストの `spec.config` で設定フォームを宣言できます。形式は Runner の `spec.config` と同じです。

```yaml
spec:
  config:
    - name: style
      type: string
      label:
        en_US: Style
        zh_Hans: 风格
      default: plain
```

ユーザーはボットの「プラグイン」タブで、プラグインの行にある「コマンド設定」をクリックし、そのボット用に各コマンドの設定を入力します。実行時は `context.config` からこの設定を読み取り、未入力の項目は `default` を使います。コマンド設定を保存していないプラグインは既定値を使います。「コマンド設定」は、`spec.config` を宣言したコマンドを 1 つ以上持つプラグインにだけ表示されます。

`spec.config` を宣言していないコマンドは変更不要です。ボットでプラグインを有効にすればそのまま使え、`context.config` は空の辞書になります。プラグイン単位の設定は引き続き `self.get_plugin_config()` で読み取れます。

## プラグイン処理

以下のコードがデフォルトで生成されます(`components/command/<command_name>.py`)。`Info`クラスの`initialize`メソッドでサブコマンド処理ロジックを登録して実装する必要があります。

```python
# Auto generated by LangBot Plugin SDK.
# Please refer to https://langbot.app/docs/en/plugin/dev/tutor.html for more details.
from __future__ import annotations

from typing import Any, AsyncGenerator

from langbot_plugin.api.definition.components.command.command import Command, Subcommand
from langbot_plugin.api.entities.builtin.command.context import ExecuteContext, CommandReturn


class Info(Command):

    async def initialize(self):
        await super().initialize()

        "Fill with your code here"
```

サブコマンドの追加:

```python
...
class Info(Command):

    async def initialize(self):
        await super().initialize()

        @self.subcommand(
            name="",  # 空文字列はルートコマンドを表す
            help="Show information of the query", # コマンドヘルプ情報
            usage="info", # コマンド使用例、コマンドヘルプに表示
            aliases=["i"], # コマンドエイリアス
        )
        async def send(self, context: ExecuteContext) -> AsyncGenerator[CommandReturn, None]:
            print(context)

            reply_text = f"Query ID: {context.query_id}\n"
            reply_text += f"command: {context.command}\n"
            reply_text += f"command_text: {context.command_text}\n"
            reply_text += f"params: {context.params}\n"
            reply_text += f"crt_params: {context.crt_params}\n"
            reply_text += f"privilege: {context.privilege}\n"
            reply_text += f"session: {context.session.launcher_type.value}_{context.session.launcher_id}\n"

            yield CommandReturn(
                text=reply_text,
            )

        @self.subcommand(
            name="field",
            help="Show information of the field",
            usage="info field",
            aliases=["f"],
        )
        async def field(self, context: ExecuteContext) -> AsyncGenerator[CommandReturn, None]:
            print(context)

            field_name = context.crt_params[0]
            field_value = getattr(context, field_name)

            yield CommandReturn(
                text=f"{field_name}: {field_value}",
            )
```

このコードでは、`@self.subcommand`デコレータを通じて`send`関数がサブコマンドとして登録され、コマンドコンテキスト(ExecuteContext)情報を出力し、それを返信メッセージに連結します。

### サブコマンド登録

`name`はサブコマンド名です。空のままにすると、メインコマンドを処理することを意味します。空でない場合、2番目のパラメータをコマンドとして照合します。例えば:

- `!info`は、name=""のサブコマンドに一致
- `!info field`は、name="field"のサブコマンドに一致
- `!info field value`は、name="field"のサブコマンドに一致し、`value`がサブコマンドパラメータ
- 特に、`name="*"`は、一致しないすべての第1レベルサブコマンドに一致し、`info`の後の各セクションをパラメータとして渡します。例えば`!info 123`、`!info abc`。ユーザーの入力に応じて、`context.crt_params`から`['123']`または`['abc']`を取得できます。

サブコマンド関数では、`context`変数を通じてコマンドパラメータを読み取ることができます。

class ExecuteContext(pydantic.BaseModel):
    """単一コマンド実行コンテキスト"""

    query_id: int
    """リクエストID"""

    session: provider_session.Session
    """このメッセージのセッションオブジェクト"""

    command_text: str

    command: str
    """コマンド名"""

    crt_command: str
    """現在のコマンド

    マルチレベルコマンドでは、crt_commandは現在のコマンド、commandはルートコマンド。

### コマンド戻り値

コマンド戻り値(CommandReturn)は、現在テキスト、画像(image_url、画像リンク)、エラーの返却をサポートしています。

```python
yield CommandReturn(
    text=reply_text,
)

yield CommandReturn(
    image_url=image_url,
)
```

コマンド処理は複数のメッセージを返すことをサポートしているため、`yield`ステートメントを使用してメッセージを返してください。

具体的な戻り値については、`CommandReturn`の定義を参照してください: [langbot_plugin.api.entities.builtin.command.context.CommandReturn](https://github.com/langbot-app/LangBot/blob/master/sdk/src/langbot_plugin/api/entities/builtin/command/context.py)

## 1 つの installation、複数の用途

1 つのコマンドは**複数の会話から同時に**起動されます：

- 設定は呼び出しごとに読み取ってください。`initialize()` で読み取ってインスタンスにキャッシュしないでください。
- コマンド引数、戻り値、会話データをインスタンスフィールドやモジュールレベルの変数に残さないでください。`ExecuteContext` は今回の実行でのみ有効です。
- 同時起動ではインスタンスフィールドの書き込みが交錯します。「現在の会話」のような状態をそこに保存しないでください。呼び出しをまたいで保持するデータは Host ストレージに置き、キーに会話の識別子を含めてください。
- installation 単位でプロセス内キャッシュを保持する場合は、`on_installation_revoked(binding)` で解放してください。

完全な仕様は[認証プラグインと共有実行](/ja/plugin/certified-plugins)を参照してください。

## プラットフォームのコマンドメニュー

ボットの「プラグイン」タブで「プラットフォームに登録」をオンにし、有効なプラグインが提供するコマンドを選びます。
設定を保存したら「今すぐ同期」をクリックできます。登録はプラットフォーム側のすべてのコマンド（管理画面で手動設定したものを含む）を上書きします。
オフにすると、それまで管理していたコマンド一覧を消去します。現在このパネルは Telegram と Discord でのみ表示されます。

同名のコマンドはプラグイン一覧の順で重複を除き、上にあるプラグインを優先します（コマンド照合と同じ規則です）。説明はマニフェストの `metadata.description` から
Workspace のメッセージ言語で選び、対応していれば多言語版も登録します。プラットフォームの制限を満たさないコマンドは登録されず、
画面に理由が表示されます。Telegram は最大 100 件、名前は `[a-z0-9_]{1,32}`、説明は 1〜256 文字です。
Discord は最大 100 件のグローバルなチャット入力コマンドで、名前は Unicode の命名規則に従い 1〜32 文字、
説明は 1〜100 文字、各コマンドに任意の文字列引数 `args` が 1 つ付きます。

Telegram は引き続きテキストメッセージで実行されるため、ボットのプレフィックスに `/` を含める必要があります。Discord はまずインタラクションを遅延応答し、
`message.received` に変換してプレフィックスの検証を省略し、返信はインタラクションの followup で送ります。ほかのイベント種別には影響しません。

ボットの起動、設定の保存、プラグインの変更時に自動で同期し、内容が変わっていなければプラットフォームへの書き込みを省略します。
`GET /api/v1/platform/bots/{uuid}` は `platform_command_sync` とフィルタの診断を返します。
手動同期は `POST /api/v1/bots/{uuid}/platform-commands/sync`（`resource.manage` が必要）で、
MCP ツール `sync_bot_platform_commands` に対応します。現時点では Telegram の既定スコープと Discord のグローバルスコープを使います。

プラットフォームの制限は [Telegram BotCommand](https://core.telegram.org/bots/api#botcommand)、
[setMyCommands](https://core.telegram.org/bots/api#setmycommands)、
[Discord Application Commands](https://docs.discord.com/developers/interactions/application-commands)、
[インタラクション応答](https://docs.discord.com/developers/interactions/receiving-and-responding)に従います。
