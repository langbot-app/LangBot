## ワンラインインストール（lbctl）を使用

```bash
lbctl upgrade --yes
```

データをバックアップし、最新の安定版へアップグレードして再起動します。アップグレードに失敗した場合、ネイティブデプロイは自動で元に戻り、Docker デプロイは復旧用にバックアップが残ります。すでに最新バージョンの場合は、その旨を表示するだけで何も変更しません。

- 計画を確認：`lbctl upgrade --dry-run`
- 指定したバージョンにアップグレード：`lbctl upgrade --version v4.11.8 --yes`
- lbctl 自体の更新：`lbctl update`、またはワンラインインストールを再実行

詳しくは [lbctl で LangBot を管理する](/ja/deploy/lbctl#langbot-のアップグレード)を参照してください。

## パッケージマネージャー（uvx）を使用

LangBotをデプロイしたディレクトリで再度実行してください:

```bash
uvx langbot@latest
```

このコマンドは最新バージョンのLangBotをダウンロードして起動します。

## Dockerを使用(またはDockerベースのワンクリックデプロイ)

<Tip>
`docker compose` でデプロイしたインスタンスは [lbctl に移行](/ja/deploy/lbctl#既存の-docker-compose-デプロイを-lbctl-に移行する)できます。移行後は `lbctl upgrade --yes` だけでアップグレードでき、毎回事前にデータがバックアップされます。以下は lbctl を使わない場合の手動の手順です。
</Tip>

LangBotをクローンしたディレクトリで実行してください:

```bash
git pull
```

`docker/`ディレクトリで実行してください:

```bash
docker compose up --force-recreate --pull always -d
```

このコマンドは最新のLangBotイメージをプルしてコンテナを再構築します。

<Info>
4.3.0バージョンでは`docker-compose.yaml`ファイルの内容と場所が変更されました。以前のバージョンから更新した場合は、[ドキュメントに従って再デプロイ](/en/deploy/langbot/docker)してください。
</Info>

## 手動デプロイ

[リリース](https://github.com/langbot-app/LangBot/releases)ページのAssetsセクションから最新リリースの`langbot-<version>-all.zip`をダウンロードし、元のデプロイディレクトリに展開して再起動してください。

## アップグレード時の注意点（メッセージポリシー・システムコマンド・チャットへの名称変更）

「パイプライン」と従来のグローバルコマンド設定を使っていた 4.11 以前からアップグレードする場合、マイグレーションにより従来の動作が維持されます。アップグレード後に次の点を確認してください：

- **「パイプライン」から「チャット」への名称変更**：WebUI とドキュメントの「パイプライン / Pipeline」は**チャット / Chat** に統一されました。既存データ、ルート、API/CLI の識別子は引き続き互換性があります。
- **メッセージポリシーをチャットからボットへ移動**：これまでチャットにあったトリガー条件（グループ応答ルール、アクセス制御、無視ルール、メッセージ集約）、安全（コンテンツフィルタ、レート制限）、共通出力の設定は、ボットの**イベントルーティング → メッセージポリシー**に移り、チャット・Agent・プラグインコマンドのすべてに適用されます。既存ボットの既定ポリシーは「何もブロックせず、何も変更しない」になり、従来のパイプライン設定はルートの上書きとして引き継がれます。
- **プラグインはボットで有効化**：ボットの**イベントルーティング → プラグインとコマンド**タブでプラグインを有効化します（コマンドとチャットイベントフック（旧 EventListener）の両方を制御）。チャット側のプラグイン一覧は AI が呼び出せるツールのみを制御します。移行時には既存ルートのプラグイン選択とコマンド紐付け済みプラグインが引き継がれます。
- **組み込みシステムコマンドによる `EssentialCommands` の置き換え**：12 個のシステムコマンド（`/help`、`/new`/`/reset`、`/stop`、`/retry`、`/undo`、`/whoami`、`/status`、`/usage`、`/model`、`/tools`、`/plugins`、`/version`）が組み込まれ、同名プラグインコマンドより優先されます。新しいボットの既定プレフィックスは `/` です。`data/config.yaml` で `!` や `！` を使っていた場合は、アップグレードチェックからワンクリックで維持できます。
- **セッション監視でのボット管理者設定**：従来の `command_settings.admins` は廃止されました。管理者専用コマンドの権限は、ボットの**セッション監視**タブで設定した管理者リストを参照します（`/whoami` で `person_10001` などの送信者 ID を確認できます）。空の場合は誰も管理者コマンドを実行できません。
- **アップグレードチェックアシスタント**：アップグレード後、ボットページとチャットページ上部に**アップグレードチェック**バナーが表示され、プレフィックス変更、同名プラグインや `EssentialCommands`、管理者未設定、自動有効化されたプラグイン、ボット既定へ昇格可能なルート上書き、移動されたチャット設定を確認・ワンクリック調整できます。
