<Warning>

  - Kubernetes クラスタの基本操作（`kubectl`、Namespace、Deployment、Service、PVC）
  - コンテナ間ネットワークと永続ストレージの設定方法
</Warning>

LangBot リポジトリの `docker/` ディレクトリには、すぐに使える Kubernetes マニフェスト [`kubernetes.yaml`](https://github.com/langbot-app/LangBot/blob/master/docker/kubernetes.yaml) が用意されています。本ページはこのマニフェストのデプロイガイドで、Docker Compose デプロイと最も異なる部分である **Box サンドボックスランタイム** に焦点を当てます。

## コンポーネント構成

マニフェストは `langbot` ネームスペースに以下のコンポーネントを作成します：

| コンポーネント | 説明 | ポート |
| --- | --- | --- |
| `langbot` | メインアプリ（WebUI + webhook） | 5300 / 2280-2290 |
| `langbot-plugin-runtime` | プラグインランタイム | 5400 |
| `langbot-box` | Box サンドボックスランタイム（任意） | 5410 |

永続ストレージ：`langbot-data`、`langbot-plugins`、`langbot-plugin-runtime-data`、`langbot-plugin-runtime-state` の 4 つの PVC。Box ワークスペースのルートは PVC ではなくノード上の `hostPath`（`/app/data/box`）を使用します。

## クイックスタート

```bash
# リポジトリをクローン
git clone https://github.com/langbot-app/LangBot
cd LangBot/docker

# すべてのコンポーネントをデプロイ
kubectl apply -f kubernetes.yaml

# 状態を確認
kubectl get all -n langbot
```

旧 Skill とローカルアセットを移行する場合、Core は移行を完了してから HTTP サービスを開始します。マニフェストの `startupProbe` は起動に約 30 分を許容します（`periodSeconds: 10`、`failureThreshold: 180`）。移行する履歴データ量に応じて `failureThreshold` を調整してください。起動プローブの成功後に、既存の liveness/readiness プローブが有効になります。各コンポーネントはイメージ内にインストール済みの Python 環境を使い、Pod 起動時に `uv sync` を実行しません。

ポートフォワードで WebUI にアクセスできます：

```bash
kubectl port-forward -n langbot svc/langbot 5300:5300
# http://localhost:5300 にアクセス
```

本番環境では Ingress + TLS での公開を推奨します（マニフェストにはコメントアウトされた Ingress / LoadBalancer / NodePort の例が含まれているので、必要に応じてコメントを解除してください）。

### SeekDB / Milvus / Valkey Search を使用する場合

デフォルトイメージには Chroma、Qdrant、pgvector のサポートだけが含まれます。SeekDB（組み込み埋め込みモデルを含む）、Milvus、Valkey Search を使う場合は、`langbot` Deployment のイメージを対応するサフィックス付きのタグ（`-seekdb`、`-milvus`、`-valkey`。例：`rockchin/langbot:latest-milvus`、`rockchin/langbot:vX.Y.Z-milvus`）に変更し、`vdb.use` を設定してください。プラグインランタイムと Box はデフォルトイメージのままで構いません。

## Box サンドボックスランタイム

`langbot-box` はサンドボックスツール（`exec` / `read` / `write` / `edit` / `glob` / `grep`）、Skill スクリプト実行、サンドボックスのドラフト公開、stdio モードの MCP サーバーを提供します。これは**任意のコンポーネント**です。Skill の管理、有効化、読み取り専用リソースへのアクセスは Core が提供し、Box は不要です。実行とサンドボックスのドラフト公開には Box が必要です。デプロイしない場合は `langbot` に `BOX__ENABLED=false` を設定してください。

### 仕組みと重要な制約

LangBot 公式イメージには **nsjail と Docker CLI** が含まれ、dockerd は含まれません。このマニフェストは Docker バックエンド用にノードの Docker socket（`/var/run/docker.sock`）をマウントし、ノードのデーモンがサンドボックスコンテナを作成します。Pod 内で dockerd は実行しません。

ここから**重要な制約**が生じます：実際にサンドボックスコンテナを作成するのは**ノード上の Docker デーモン**であり、bind-mount のパスを**ノードのファイルシステム**視点で解決します。したがって Box ワークスペースのルートは、以下の 3 か所で**同一の絶対パス**でなければなりません：

1. ノード上の実際のパス
2. `langbot-box` コンテナ内のマウントパス
3. それが作成する各サンドボックスコンテナ内のマウントパス

これがマニフェストで通常の PVC ではなく `hostPath`（`/app/data/box` に固定）を使う理由です。PVC のパスは Pod の mount namespace 内にしか存在せず、ノードの dockerd からは見えません。既存の `legacy` デプロイとの互換性のため、Core の Box マウントと同一ノードの `podAffinity` を残しています。データベース保存とネットワークモードへの移行後は、Core のこのマウントと対応するアフィニティを削除できます。Box とノードの Docker デーモン間では同一パスが引き続き必要です。手順は [Skill のアップグレード説明](/ja/usage/skills/readme)を参照してください。

<Warning>
  このマニフェストは SQLite と `ReadWriteOnce` ストレージを使う単一 Core デプロイがデフォルトです。共有 Box ディレクトリを削除しても、`replicas` の増加だけで高可用性は実現しません。複数 Core では、データベース、インスタンス ID、Runtime 制御接続を別途設計する必要があります。
</Warning>

### 接続と設定

- `langbot` は WebSocket で Box ランタイムに接続します。エンドポイントは ConfigMap の `BOX__RUNTIME__ENDPOINT: ws://langbot-box:5410` で指定します。

<Note>
  コンテナ内のデフォルトホスト名は `langbot_box`（アンダースコア付き）ですが、アンダースコアは有効な Kubernetes DNS 名ではありません。そのためマニフェストでは、有効な Service 名 `langbot-box` を使ってエンドポイントを**明示的に**指定する必要があり、コンテナ内のデフォルト値に依存できません。
</Note>

- Box のワークスペースルートは自身の `LANGBOT_BOX_CONFIG` で設定します。マニフェストでは `local.host_root` を `/app/data/box` に設定し、このパスを `local.allowed_mount_roots` に含めています。その他の実行設定は Core が INIT RPC で渡し、Box は自身の `BOX__*` 環境変数を読み取りません。ネットワークモードでは Core のローカルルートを受け付けません。Core の `BOX__LOCAL__*` と `SKILLS__ROOT` は、既存の `legacy` デプロイと移行元の指定用に残しています。

### セキュリティに関する注意

ノードの Docker socket をマウントすると、Box ランタイム（およびサンドボックス内で実行される任意のコード）にノードへの**実質的な root 権限**を与えることになります。Box はこのワークロードを信頼できるノードにのみデプロイし、できればテイント/トレラレーションで隔離した専用ノードプールを使用してください。より強い隔離境界が必要な場合は、`box.backend` を `e2b` に切り替え（`E2B_API_KEY` を設定）、`docker.sock` のマウントと hostPath を削除します。詳細は[サンドボックス設定](/ja/usage/sandbox/config)を参照してください。

### Box の準備完了を確認する

```bash
# Box ランタイムのログ（選択された backend が表示されるはず、例: "using backend: docker"）
kubectl logs -n langbot -l app=langbot-box -f

# langbot が Box ランタイムに接続したことを確認
kubectl logs -n langbot -l app=langbot | grep -i "box runtime"
```

## サンドボックスが不要な場合

サンドボックス機能が不要な場合は、マニフェストから `langbot-box` の Deployment / Service を削除し、`langbot` Deployment に `BOX__ENABLED=false` を設定して接続失敗の警告ログを回避してください。
