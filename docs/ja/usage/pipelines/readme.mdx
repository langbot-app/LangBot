チャット（旧パイプライン）は、AI がメッセージをどう処理して返信するか（使用するランナー、モデル、プロンプト、AI が呼び出せるプラグインツール・MCP サーバー・スキル）を定義します。ボットの「イベントルーティング」で「メッセージ受信」をチャットに渡します。1 つのチャットを複数のボットで使えます。

LangBot は最初の起動時に既定のチャットを自動作成します。ボットを作成すると、そのメッセージは既定のチャットにルーティングされます。最初のモデルを作成すると、既定のチャットのモデルとして設定されます。

<Info>
トリガー条件（グループ応答ルール、アクセス制御、無視ルール、メッセージ集約）、安全（コンテンツフィルタ、レート制限）、共通出力（長文、強制遅延、送信者への @、引用、例外通知）はボットの「メッセージポリシー」に移り、プラグインのコマンドとイベントリスナーもボットで有効にするようになりました。[ボット](/ja/usage/platforms/readme#イベントルーティングプラグインメッセージポリシー)を参照してください。チャットのプラグイン一覧は、AI が呼び出せるプラグインツールを決めるだけです。
</Info>

異なるシナリオに適応するために、異なるボット用に複数のチャットを作成できます。

チャットでは以下の機能を設定できます:

## AI機能

以下を選択して使用できます: `組み込みエージェント`、[`Dify`](https://dify.ai/)、[`n8n`](https://n8n.io/)

AI機能は主に2つの部分に分かれています: ランナーの選択とランナーパラメータの設定。

ランナーは、メッセージを処理するために大規模モデルをスケジュールする方法を定義します。デフォルトは`組み込みエージェント`で、これはLangBotによって実装された複数ラウンドのエージェント戦略です。このランナーが選択されている場合のみ、LangBot内で設定されたモデルとツールが使用されます。

### グループチャットのコンテキスト

「実行方式」の**グループチャットのコンテキスト**で、グループチャットの会話記憶の分け方を選びます。

- **メンバーごとに独立**（既定）：グループの各メンバーが自分の会話を持ちます。ボットはそのメンバーの過去の発言を覚え、他のメンバーの会話とは混ざりません。
- **グループで共有**：グループ全体で 1 つの会話を使い、ボットは全員の過去の発言を参照します。

この設定は、組み込み Agent、外部 Agent プラットフォーム（Dify など）が受け取る会話、サンドボックスのセッション、「コンテキストをリセット」の範囲に適用されます。個人チャットには影響せず、ボットのメッセージポリシーにあるアクセス制御・グループ応答ルール・レート制限は引き続きグループ単位です。

<Note>
この設定を保存したことのないチャットも「メンバーごとに独立」として動作します。グループで 1 つの会話を使い続けたい場合は、チャットで「グループで共有」に変更してください。
</Note>

ボットのセッションモニターでは、グループチャットは常にメンバーごとに表示されます。「同じグループ」をクリックすると、そのグループのセッションだけを表示できます。チャットが「グループで共有」の場合にメンバーのセッションをリセットすると、グループ全体の会話がリセットされ、ダイアログにもその旨が表示されます。

### 会話変数
外部Agent プラットフォームを使用する場合、LangBotは以下のパラメータを明示的に渡します。これらをAgent プラットフォームワークフローの開始ノードに追加できます(以下の画像はDifyの例です):

- `launcher_type`: ランチャーオブジェクトタイプ、プライベートチャットの場合は`person`、グループチャットの場合は`group`
- `launcher_id`: ランチャーオブジェクトID、プライベートチャットの場合はユーザーID、グループチャットの場合はグループID
- `sender_id`: 送信者ID
- `user_message_text`: ユーザーメッセージのプレーンテキスト
- `session_id`: ユーザーセッションID。プライベートチャットの場合は`person_<id>`。グループチャットの場合、「グループで共有」では`group_<グループID>`、「メンバーごとに独立」では`groupmember_<グループIDの長さ>_<グループID>_<送信者ID>`
- `conversation_id`: 文字列、ユーザーセッションID、LangBotによって生成されます。ユーザーがセッションをリセットした後に再生成されます
- `msg_create_time`: 数値型、このメッセージが受信されたタイムスタンプ(秒)
- `group_name`: グループ名、グループメッセージを受信した場合のみ設定されます
- `sender_name`: 送信者名

[プラグインを通じて任意の変数をカスタマイズできます](/en/plugin/dev/apis/common.html#set-request-variables)。

### プロンプトライブラリ

組み込み Agent を使う場合、「プロンプト」欄に 2 つのボタンがあります。

- **プロンプトライブラリ**：LangBot Space で共有され審査を通過したプロンプトをダイアログで検索します。チャットでは会話プロンプト、Agent では Agent プロンプトが既定で表示され、もう一方にも切り替えられます。「置き換え」または「追加」を選んだあと、保存してください。
- **共有**：現在のプロンプトを LangBot Space に投稿します。API キーやトークンなどの認証情報を含むと投稿できず、メールアドレス・電話番号・内部 URL を含む場合は確認が必要です。審査通過後に公開されます。

LangBot アカウントを連携すると、プロンプトをお気に入りに登録できます。お気に入りはアカウントに紐づき、LangBot Space のウェブサイトでも確認できます。

## その他の設定

チャットのランナープラグインが起動中の場合、LangBot はインストール済みで有効なプラグインを最大 30 秒待ってから利用不可を報告します。プラグインのインストールや権限確認を自動で行うことはありません。ランナーが見つからない場合は、同じワークスペースの**プラグイン**画面でインストール、有効化、権限確認をチェックしてください。ダウンロード、依存関係のインストール、初期化に失敗した場合は、インストールタスクとランタイムログを確認し、原因を解決して再試行してください。プラグインが実行中でも対象のランナーがない場合は、バージョンを確認し、チャットの AI 設定で利用可能なランナーを選択してください。監視のエラー記録には失敗の詳細が含まれます。

設定フォームの説明を参照してください。

## チャットの削除

ボットのイベントバインディングがまだ参照しているチャットは削除できず、使用中のボットがエラーに表示されます。先にそれらのバインディングを別のチャットまたは Agent に変更してから削除してください。Agent も同様です。
