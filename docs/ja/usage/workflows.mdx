---
title: "ワークフロー"
description: "メッセージ・コマンド・定期実行・プラットフォームイベントを、プラグインを書かずに決まった手順で処理します。"
---

ワークフローは、チャット・Agent・プラグインプロセッサと並ぶプロセッサです。メッセージ（またはコマンド、定期実行、プラットフォームイベント、Webhook）を受け取ると、並べた手順を順に実行します。たとえば意図の分類、モデルや API の呼び出し、情報の記憶、返信などです。天気の照会、今日の運勢、キーワード通知、定期配信、入室あいさつ、チェックインのランキングなど、これまでプラグインが必要だった多くのことをワークフローで作れます。

## ワークフローを作成する

1. **プロセッサ**を開き、**作成**から**ワークフロー**を選びます。
2. テンプレートを選びます：**空白**、**意図で振り分け**、**キーワード返信**、**API で調べて返信**。
3. 編集画面では左に**テスト実行**、右に**手順**が表示されます。

## 手順を並べる

- 手順は上から下へ自動で配置され、すべて**開始**から始まります。
- 手順の下の **+** で次の手順を追加します。2 つの手順の間に入れると、後ろの手順は新しい手順の下に移ります。
- **分類**と**条件分岐**は、分類やケースごとに分岐と**その他**の分岐を作ります。
- 手順をクリックすると右側で編集できます。前の結果を使うときは、入力欄の **{ }** から「開始 · テキスト」のように選びます。灰色の値は前回のテスト実行の値です。
- モデル未選択や存在しない結果の参照など、問題のある手順は赤く表示されます。保存すると、タイトルの横に問題の件数が表示されます。

## トリガー

**開始**をクリックしてトリガーを設定します。複数を組み合わせられます。

| トリガー | 説明 |
| --- | --- |
| メッセージ | ボットの**イベントルート**で `message.received` をこのワークフローに向けます。ボットのアクセス制御、レート制限、出力設定はそのまま適用されます。 |
| コマンド | 例：`/天気 東京`。別名、引数（スペース区切りで、最後の引数が残りすべてを受け取る）、管理者限定、利用できるボットを設定します。システムコマンドやプラグインコマンドと一緒に `/help` に表示されます。名前が重なった場合はシステムコマンド、次にプラグインコマンドが優先されます。引数が足りないと使い方を返信します。 |
| 定期実行 | 毎日、毎週、N 分ごと、または cron（ワークフローのタイムゾーン）。送信するボットと送信先を選びます。会話ごとに 1 回実行し、**返信**はその会話に送られます。 |
| プラットフォームイベント | すべての標準イベント：メッセージの編集・取り消し・リアクション、メンバーの参加・退出・ミュートとグループ情報の変更、友達申請・追加・削除、ボットのグループ招待・退出・ミュート、フィードバック、各プラットフォーム固有のイベント（WeCom カスタマーサービスのセッション開始など）。グループ単位でまとめて選べます（例：「グループ · すべて」）。各イベントの下に、対応しているボットが表示されます。「開始 · イベント · メンバー名」やリクエスト ID などの項目をそのまま挿入できます。ボットのイベントルートでもこのワークフローを選んでください。ルートにはそのイベントを処理できるワークフローだけが表示されます。 |
| Webhook | 他のシステムが生成された URL に JSON オブジェクトを `POST` すると起動します。内容は「開始 · リクエスト内容」で読めます。URL には秘密の値が含まれます。 |

## 手順

| 分類 | 手順 | 用途 |
| --- | --- | --- |
| AI | モデル応答 | プロンプトから文章を生成。直近 10 往復の会話や画像も渡せます |
| AI | 分類 | 意図で分岐 |
| AI | 情報抽出 | 注文番号や都市などの項目を取り出す |
| AI | ナレッジ検索 | ナレッジベースから関連部分を探す |
| AI | 音声合成 / 音声認識 | 音声を作る、または送られた音声を文字にする |
| 判定とデータ | 条件分岐 | 含む・等しい・より大きい・正規表現などのルールで分岐（式は不要） |
| 判定とデータ | ランダム | ランダムに 1 つ、乱数、または同じ人なら同じ日に同じ結果（今日の運勢など） |
| 判定とデータ | 記憶 | 値の保存・加算・リスト追加・削除。範囲は今回の実行・ユーザーごと・グループごと・ワークフロー全体。チェックイン、回数制限、ランキングに |
| 判定とデータ | チャット履歴 | この会話やグループの最近のメッセージ（要約など） |
| 判定とデータ | コード | サンドボックスで Python を実行（最大 10 秒）。Box が必要 |
| アクション | 返信 | 送信者に返信。画像や音声も添付可。引用と @ はボットのメッセージポリシーに従います |
| アクション | 別の会話に送信 | このボットまたは指定したボットでグループや個人に送信 |
| アクション | HTTP リクエスト | HTTP サービスを呼び出し、ステータス・本文・JSON を取得。内部アドレスは拒否されます |
| アクション | プラットフォーム操作 | Agent と同じプラットフォーム操作です。「トリガーのメッセージ・イベント」は対象の入力が不要です：このメッセージの取り消し、このメンバーのミュートや退出、この友達申請やグループ招待の承認・拒否、送信者やこのグループの照会。そのほかの標準 API（メッセージ、グループ、グループ管理、ユーザーと友達、ファイル）は入力した ID に対して実行し、アダプター固有の操作も使えます。操作を選ぶと対応するボットが表示されます。未対応のプラットフォームでは失敗します |
| アクション | 処理を引き継ぐ | チャット・Agent・別のワークフローに任せて返信させます。後に手順は置けません |

**モデル応答**、**HTTP リクエスト**、**プラットフォーム操作**は、「詳細設定」で失敗時に空の結果のまま続行できます。

## テスト実行と実行履歴

- **テスト実行**は、未保存の変更を含むキャンバス上の手順を使います。返信はここにだけ表示され、ボットには送られません。実行された手順は緑になって所要時間が表示され、通らなかった分岐は灰色になります。手順をクリックすると入出力を確認できます。
- `/コマンド 引数` と入力すると、コマンドトリガーをテストできます。
- プラットフォームイベントを受けるワークフローでは「イベント」に切り替え、イベントを選んでサンプルデータを編集し「イベントを試す」を押します。Agent のデバッグと同じく、プラットフォーム操作は模擬実行され、実際には呼び出されません。
- **実行履歴**タブでは、各実行の手順ごとの入力・出力・エラーを確認できます。メッセージによる実行はダッシュボードの実行記録にも表示されます。

## 応用：テンプレート

挿入した変数は `{{ 手順ID.結果 }}` の形です。記憶した値は `{{ memory.user.名前 }}` と書き、範囲には `run`、`user`、`group`、`workflow` を指定します。テンプレートはサンドボックス化された Jinja です。`{% for item in http_1.json.items %}…{% endfor %}` でリストを並べられ、`length`、`join`、`default`、`truncate`、`date`、`random`、`json` のフィルターが使えます。

## 制限

- 手順はツリー構造です。各手順の前の手順は 1 つだけで、分岐は合流せず、ループもありません。
- 1 回の実行は最大 300 秒です。
- **コード**手順には Box サンドボックスが必要です。
