ボットはメッセージングプラットフォームからメッセージイベントを受信し、ボットの「イベントルーティング」に従ってチャット、Agent、プラグイン処理に渡します。

## イベントルーティング・プラグイン・メッセージポリシー

ボット詳細の「イベントルーティング」には 3 つのタブがあります。

- **ルート**：イベントの種類ごとに処理先を決めます。受信メッセージはチャット（旧パイプライン）、Agent、プラグイン処理のいずれかに渡せます。条件付きのルートを複数設定でき、どれにも一致しない場合は既定のルートが使われます。
- **プラグイン**：このボットで有効にするプラグインを「すべてのプラグインを有効にする」または手動で選びます。プラグインを有効にすると、そのコマンドとイベントリスナー（メッセージライフサイクルフック）がまとめて有効になります。新しいボットではすべて有効です。ルートごとに個別に設定できます。各プラグインには、選択中のルートの処理先でフックが有効かどうかが表示されます。たとえば `PromptPreProcessing` はチャットでのみ有効です。
- **メッセージポリシー**：以前はパイプラインにあった「トリガー条件・安全・共通出力」の設定がボットに移り、チャット、Agent、プラグインコマンドのすべてに適用されます。ボットには既定のポリシーがあり、ルートごとに上書きできます。

メッセージポリシーの内容：

| 分類 | 設定 |
| --- | --- |
| トリガー条件 | グループ応答ルール（@、プレフィックス、正規表現、ランダム）、アクセス制御（ブラックリスト / ホワイトリスト）、無視ルール、メッセージ集約、引用メッセージの結合 |
| 安全 | コンテンツフィルタ、レート制限 |
| 共通出力 | 長文処理、強制遅延、送信者への @、元メッセージの引用、例外処理と各種通知文 |

補足：

- ポリシーは受信メッセージ（`message.received`）にのみ適用され、ほかのプラットフォームイベントには影響しません。
- プラグインコマンドはルートのルールより先に照合されますが、そのメッセージが本来一致するルートのポリシーを使います。一致するルートがない場合はボットの既定ポリシーが使われます。
- Agent のストリーミング返信には遅延・@・引用のみが適用され、長文処理は適用されません。プラグインが自発的に送るメッセージ（`send_message`）はポリシーの影響を受けません。
- チャットのデバッグ対話はボットを経由せず中立ポリシーを使うため、長文や @ などの効果はプレビューできません。
- 旧バージョンからのアップグレード時、既存のボットの既定ポリシーは「何もブロックせず、何も変更しない」になり、パイプラインを指す各ルートには元のパイプラインの設定がルートの上書きとしてコピーされるため、動作は変わりません。

![arch](/images/zh/deploy/bots/arch.png)

`lbctl bot get <bot>` でルート ID を確認します。`lbctl bot routes bind <bot> --binding <id> --agent <agent> --dry-run` で変更を確認した後、`--yes` で適用します。チャットに接続する場合は `--pipeline` を指定します。ルートが同時に変更された場合は競合が返るので、最新の設定を読み直してください。

<Tip>
**パブリック IP やドメインの設定が面倒ですか？** Slack、LINE、WeCom、Lark などのプラットフォームでは Webhook コールバック URL が必要で、パブリックサーバー、ドメイン、HTTPS 証明書が必要です。[LangBot Cloud](https://space.langbot.app/cloud) にはドメイン解決と HTTPS が組み込まれており、登録するだけですぐに使用できます。
</Tip>
