ボットはメッセージングプラットフォームからメッセージイベントを受信し、ボットの「イベントルーティング」に従ってチャット、Agent、プラグイン処理に渡します。

## イベントルーティング・プラグイン・メッセージポリシー

ボット詳細の「イベントルーティング」には 3 つのタブがあります。

- **ルート**：イベントの種類ごとに処理先を決めます。受信メッセージはチャット（旧パイプライン）、Agent、プラグイン処理のいずれかに渡せます。条件付きのルートを複数設定でき、どれにも一致しない場合は既定のルートが使われます。
- **プラグインとコマンド**：このボットで有効にするプラグイン（「すべてのプラグインを有効にする」または手動選択）を選び、組み込みの[システムコマンド](/ja/deploy/system-commands)とプラグインコマンドの有効化、プレフィックス（既定 `/`）、権限（`everyone` / `admins`）を設定します。有効なシステムコマンドは同名のプラグインコマンドより優先されます。プラグインを有効にすると、そのコマンドとチャットイベントフック（旧 EventListener）がまとめて有効になります。新しいボットではすべて有効です。ルートごとに個別に設定でき、各プラグインには選択中のルートの処理先でフックが有効かどうかが表示されます（たとえば `PromptPreProcessing` はチャットでのみ有効です）。
- **メッセージポリシー**：以前はパイプラインにあった「トリガー条件・安全・共通出力」の設定がボットに移り、チャット、Agent、プラグインコマンドのすべてに適用されます。ボットには既定のポリシーがあり、ルートごとに上書きできます。

メッセージポリシーの内容：

| 分類 | 設定 |
| --- | --- |
| トリガー条件 | グループ応答ルール（@、プレフィックス、正規表現、ランダム）、アクセス制御（ブラックリスト / ホワイトリスト）、無視ルール、メッセージ集約、引用メッセージの結合 |
| 安全 | コンテンツフィルタ、レート制限 |
| 共通出力 | 長文処理、強制遅延、送信者への @、元メッセージの引用、例外処理と各種通知文 |

補足：

- ポリシーは受信メッセージ（`message.received`）にのみ適用され、ほかのプラットフォームイベントには影響しません。
- プラグインコマンドはルートのルールより先に照合されますが、そのメッセージが本来一致するルートのポリシーを使います。一致するルートがない場合はボットの既定ポリシーが使われます。
- Agent のストリーミング返信には遅延・@・引用のみが適用され、長文処理は適用されません。プラグインが自発的に送るメッセージ（`send_message`）はポリシーの影響を受けません。
- チャットのデバッグ対話はボットを経由せず中立ポリシーを使うため、長文や @ などの効果はプレビューできません。
- 旧バージョンからのアップグレード時、既存のボットの既定ポリシーは「何もブロックせず、何も変更しない」になり、パイプラインを指す各ルートには元のパイプラインの設定がルートの上書きとしてコピーされるため、動作は変わりません。

![arch](/images/zh/deploy/bots/arch.png)

`lbctl bot get <bot>` でルート ID を確認します。`lbctl bot routes bind <bot> --binding <id> --agent <agent> --dry-run` で変更を確認した後、`--yes` で適用します。チャットに接続する場合は `--pipeline` を指定します。ルートが同時に変更された場合は競合が返るので、最新の設定を読み直してください。

**グループごとのルーティング**：特定のグループに専用のチャットまたは Agent を使わせるには、ボットの**セッション**タブでそのグループのセッションを選びます。タイトルの下に完全な**グループ ID**（コピー可）が表示されます。**このグループのルーティングを設定**をクリックすると、イベントルートの先頭に「チャット種別 = グループ、チャット ID = そのグループ」のルールが追加されます。処理先を選んで保存すれば、他のグループは下のルールのまま動作します。実行詳細ドロワーにも同じグループ ID と入口が表示されます。

## セッション監視とアップグレードチェック

- **セッション監視**：セッション一覧と実行履歴では処理方法による絞り込みができ、4 種類のバッジ（**AI**、**コマンド**（システムコマンド・プラグインコマンド・コマンド拒否を区別）、**プラグイン**（イベントプロセッサー／フックによる横取り）、**ポリシーでブロック**（該当ルールとボット既定／ルート上書きの別を表示））を確認できます。実行詳細には 4 段階の**メッセージポリシー**タイムライン（**受付** → **ライフサイクルフック** → **プロセッサ** → **出力処理**）が表示され、**ルート**タブには各ルートの**直近 24 時間**の件数（AI / コマンド / プラグイン / ブロック）が表示されます。
- **ボット管理者**：ボットの**セッション**タブで管理者を設定できます（送信者 ID は `/whoami` で確認）。管理者リストが空の場合、管理者専用のシステムコマンド・プラグインコマンドは誰も実行できません。
- **アップグレードチェック**：旧バージョンからのアップグレード後、ボットページおよびチャットページの上部に**アップグレードチェック**バナーが表示され、プレフィックス変更、システムコマンドとの同名衝突や `EssentialCommands`、管理者未設定、自動有効化されたコマンドプラグイン、ボット既定に昇格できるルート上書き、チャット設定の移動状況を確認・ワンクリック調整できます。
