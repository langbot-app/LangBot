# 购买意向留资

让 AI 客服自动发现「想买」的客户：插件在每次 AI 回复后，用你选定的模型、按你写的评分标准给客户的**购买意向打 0–100 分**，并识别**合规风险**。达到中意向（默认 ≥ 30 分）就在这次回复后面附上一句请求联系方式的话术（每个客户只问一次）；客户留下手机号 / 微信 / 邮箱后，插件从整段对话中**提取公司、场景、用量、预算等线索字段**，连同**联系方式、评分和全部对话记录**通过 [Resend](https://resend.com) 发到你指定的邮箱。

适用于任意平台的私聊（微信公众号、企业微信客服、Telegram、QQ……）。

## 效果一览

1. 客户和 AI 正常聊天，例如问「年付多少钱？能开发票吗？」
2. AI 回复后，插件给出评分（例如 75 分 · 高意向，命中「询价」「发票」）；达到请求分数线时，这次回复末尾多一句：「为了更好地为您服务，方便留下您的手机号或微信号吗？我们的顾问会尽快与您联系。」
3. 客户回复「138 0013 8000」。插件识别到联系方式，立刻发出一封邮件：
   - 标题：`【购买意向】138 0013 8000 · 微信公众号`
   - 正文：联系方式、用户 ID、来源 Bot、意向判断理由、留资时间、首次联系时间、消息总数，以及完整对话；
   - 附件：`conversation-时间.txt`（完整对话记录）。
4. 下一次 AI 回复末尾附上致谢：「已收到您的联系方式，我们的顾问会尽快与您联系，感谢您的信任！」
5. 之后不再判断、不再追问这个客户。如果客户没留联系方式，也不会再问第二次。

## 配置步骤

### 第 1 步：准备 Resend

1. 注册 [resend.com](https://resend.com)。
2. **Domains → Add Domain**，添加你们自己的发信域名（例如 `example.com`），按提示在域名 DNS 里添加记录，等状态变为 **Verified**。
3. **API Keys → Create API Key**，权限选 **Sending access**，复制生成的 `re_` 开头的 Key（只显示一次）。

> 未验证域名时，Resend 只允许用 `onboarding@resend.dev` 发给注册 Resend 的那个邮箱，仅适合测试。

### 第 2 步：安装插件并确认权限

安装后在插件详情页**确认权限**：

| 权限 | 用途 |
| --- | --- |
| `models.invoke` | 调用模型判断购买意愿、识别联系方式 |
| `storage.plugin` | 记录每个客户「已询问 / 已留资」的状态 |
| `monitoring.messages`（消息历史查询，只读） | 读取对话记录，用于判断和发送邮件 |

### 第 3 步：填写插件配置

| 配置项 | 填什么 |
| --- | --- |
| 判断用的模型 | 选一个对话模型。每次 AI 回复后都会调用一次，建议选响应快、成本低的模型 |
| 购买意向评分标准（提示词） | 描述哪些信号加分、哪些扣分，可以直接粘贴你们的「关键词 + 分值」清单。模型按语义理解（含繁体、同义说法）给整段对话打 0–100 分。已有一份通用默认值 |
| 高意向分数线 | 默认 60，达到即为高意向 |
| 请求联系方式的分数线 | 默认 30：中意向（30–59）和高意向都会被请求一次联系方式；设成和高意向分数线相同则只问高意向 |
| 合规风险判定 | 命中这些情形（默认：刷单、抢票、破解、爬微信/银行、翻墙/VPN 等）的会话标记为「合规风险」：**不请求联系方式、不发销售邮件**，在页面中单独列出供人工审核 |
| 需要提取的线索字段 | 留资后从整段对话里提取的字段，默认：公司名称、行业、使用场景、目标网站或数据来源、预估月请求量或数据量、预算范围、上线时间、联系人姓名、职位、企业邮箱、微信或电话、现有供应商。放在邮件开头和页面详情中，没提到的显示「未提及」 |
| 参与判断的对话条数 | 每次判断读取最近多少条对话，默认 20，最多 100 |
| 请求联系方式的话术 | 达到请求分数线时附加在 AI 回复后的固定文案 |
| 收到联系方式后的致谢 | 留资后附加在下一次 AI 回复后的文案，留空则不发 |
| Resend API Key | 第 1 步的 `re_` 开头的 Key |
| 发件地址 | 已验证域名下的地址，例如 `leads@example.com`，也可以写成 `销售线索 <leads@example.com>` |
| 收件邮箱 | 接收线索的邮箱，可填多个 |

### 第 4 步：在流水线中启用

插件在流水线里工作：确认客户聊天用的 Bot 收到消息后交给一条**流水线**处理，并且这条流水线允许使用本插件。

### 第 5 步：测试

用自己的账号和 Bot 聊天，问一些和购买相关的问题（价格、合同、试用），看 AI 回复末尾是否出现请求话术；回复一个手机号，检查收件邮箱。

## 查看判断记录（插件页面）

插件自带一个「**留资判断记录**」页面：在 LangBot 侧边栏的插件页面里打开。

- **顶部统计**：会话数、判断次数、已请求联系方式、已留资、已发邮件。
- **会话列表**：每个私聊用户一行，包括状态（未达到 / 已询问 / 已留资）、最近一次判断及理由、判断次数（其中强意愿次数）、联系方式和邮件发送结果。可以按状态筛选（含「有异常」），也可以按用户 ID 或联系方式搜索。
- **会话详情**：点击任意一行，右侧展示这个会话的**判断时间线**：每次判断的结论、理由、当时用户说的话和 AI 的回复，以及请求联系方式、识别到联系方式、邮件发送和异常记录；下方附最近 30 条对话。

每个会话保留最近 100 条事件。页面只读，不会改动任何数据。

## 联系方式怎么识别

- 先用规则识别：中国大陆手机号（可带 `+86`、空格或横线）、带区号的座机（如 `010-12345678`）、邮箱、「微信 / vx / wx」后面的微信号。
- 规则识别不到时，再让模型从这条消息里提取（例如「加我 QQ 123456789」）。模型被要求不得编造，没有联系方式时返回空。
- 识别到之前，客户的每条消息都会检查一次；之后不再检查。

## 常见问题

**邮件没收到**
查看插件日志中的 `LeadCapture email failed (...)`：
- `not_configured`：API Key、发件地址或收件邮箱没填。
- `http_403:validation_error`：发件域名还没在 Resend 验证，或发件地址不在该域名下。
- `http_401` / `http_403`：API Key 错误或权限不足。
- `network:...`：服务器无法连到 `api.resend.com`。

发送失败后，会在之后的 AI 回复时自动重试，**最多共 3 次**。

**一直没有出现请求话术**
确认模型已选择、判断标准写得足够具体；也可以在插件日志里查看是否有 `intent evaluation failed`。已经问过一次的客户不会再问。

**AI 回复变慢了**
每次 AI 回复后要额外调用一次模型做判断，会增加这次回复的耗时（通常 1～3 秒）。可以换更快的模型，或减少参与判断的对话条数。微信公众号 auto 模式下回复本就是异步推送，影响不明显。

**AI 回复里的图片**
附加话术时，这次回复会以文字形式发送；如果 AI 的这条回复含图片，图片会显示为占位文字。

## 限制与说明

- 只处理私聊，不处理群聊。
- 每个客户只询问一次联系方式；状态按「Bot + 用户」保存。重装插件会清空所有客户的状态。
- 邮件中包含客户的联系方式和完整对话，请确认符合你们的隐私与数据管理要求。
- 对话记录来自 LangBot 的消息记录，最多导出 5000 条。

## 给开发者

一个 EventListener（`components/event_listener/lead.py`）：

- `NormalMessageResponded`：判断意愿，并通过 `reply_message_chain` 在 AI 回复后附加请求话术或致谢；
- `PersonMessageReceived`：在已询问状态下识别联系方式，并调用 Resend 发送邮件。

对话来自只读的 `monitoring.messages` Workspace 操作；任何失败都只记录日志，不会影响对话本身。

```bash
uv venv
uv pip install -r requirements-dev.txt
uv run pytest -q
uv run ruff check .
```
