# 人工客服转接

让 AI 客服在需要时把用户交给真人：用户发出「转人工」之类的关键词后，对话会推送到你们员工所在的平台（例如 Slack 频道、飞书群、QQ 群），员工直接回复，回复会发回给用户。接管期间 AI 不会插话，员工结束接管后自动恢复 AI 回复。

**客户侧**可以是 LangBot 支持的任意平台（微信公众号、企业微信客服、Telegram、QQ……）；**员工侧**目前支持 **Slack、飞书、QQ（OneBot v11）**。

## 效果一览

1. 用户发送含关键词的消息（例如「转人工」），AI 停止回复。
2. 用户收到提示：「已为您转接人工客服，请稍候，客服会在这里回复您。」
3. 员工所在的群 / 频道收到一条「📩 人工客服请求」，包含来源 Bot、用户（已脱敏）、关键词和原文。
4. 紧接着回复一条「👤 用户详情」：完整用户 ID、历史消息数、首次联系时间和最近若干条对话。
5. 用户在接管期间继续发的消息，会以回复「人工客服请求」的形式转给员工。
6. 员工**回复（引用）**任意一条转来的消息，用户就能收到；成功后出现 ✅。
7. 员工回复 `!close` 结束接管，用户收到「人工客服已结束本次服务，后续将由 AI 助手继续为您解答。」，之后恢复 AI。

> 在 Slack 里，「回复」就是在消息的 thread 里发言；在飞书 / QQ 里，就是对消息点「回复」（引用）。

## 准备工作

| 需要 | 说明 |
| --- | --- |
| **客户侧 Bot 能主动发消息** | 员工回复要通过 Bot 主动推送给用户。微信公众号请用 **auto 模式**（一般需要认证服务号）；其他平台通常默认支持。 |
| **员工侧 Bot** | Slack、飞书或 QQ（OneBot v11）的 Bot，已接入 LangBot 并拉进员工群 / 频道。 |
| **LangBot 管理员权限** | 用来安装插件、确认权限、配置 Bot。 |

## 配置步骤

### 第 1 步：配置客户侧 Bot

1. 确认客户聊天用的 Bot 收到消息后交给一条**流水线**处理（不能是 Agent），并且这条流水线允许使用本插件。插件靠流水线里的事件监听在接管期间拦住 AI 回复。
2. 微信公众号：把「接入模式」改为 **auto**，并建议**清空「加载提示语」**，否则接管期间用户每发一条都会先看到「AI正在思考中…」。

### 第 2 步：准备员工侧 Bot 和群

- **Slack**：创建 Slack 应用并接入 LangBot（可用「Slack 快速配置」）。应用至少需要 `chat:write`、`app_mentions:read`、`channels:history` 权限（私有频道加 `groups:history`），并订阅 `app_mention`、`message.channels`（私有频道加 `message.groups`）事件，改完权限要 **Reinstall to Workspace**。在频道里发 `/invite @应用名` 把应用拉进去。
- **飞书**：在飞书开放平台创建企业自建应用并接入 LangBot，开启机器人能力，订阅接收消息事件，并把机器人加进员工群。
- **QQ（OneBot v11）**：按 LangBot 文档接入 OneBot 实现，并把机器人账号加进员工群。

### 第 3 步：找到员工群 / 频道的 ID

插件需要的是 **ID**，不是群名。

- **通用方法（所有平台都适用）**：在员工群里 **@机器人随便发一句话**，然后在 LangBot 打开员工侧 Bot 的详情页，查看最近的**事件日志**，「收到消息」事件里的会话 ID（`chat_id`，或 `group_xxx` 中 `group_` 后面的部分）就是群 ID。
- **Slack 快捷方法**：点频道顶部的频道名称，弹窗最底部的 **Channel ID**（形如 `C0123ABCD45`）；或右键频道 → 复制链接，取 `…/archives/` 后面那段。
- **飞书**：群 ID 形如 `oc_xxxxxxxx`，用上面的通用方法获取最方便。
- **QQ**：就是 QQ 群号。

如果员工侧想用**私聊**（发给某一位员工），会话类型选「私聊」，ID 填该员工的用户 ID，同样可以用通用方法找到。

### 第 4 步：安装插件并确认权限

安装本插件后，在插件详情页**确认权限**：

| 权限 | 用途 |
| --- | --- |
| `bot.message.send` | 给用户和员工发消息 |
| `storage.plugin` | 保存接管会话 |
| `bot.read` | 读取 Bot 名称和平台类型（显示来源、决定 Slack 格式转换） |
| `monitoring.messages`（消息历史查询，只读） | 生成「用户详情」里的历史消息数、首次联系时间和最近对话 |

前两项不确认插件不会工作；后两项缺失时插件照常转接，只是信息少一些。

### 第 5 步：填写插件配置

| 配置项 | 填什么 |
| --- | --- |
| 客户所在 Bot | 第 1 步的客户侧 Bot |
| 员工所在 Bot | 第 2 步的员工侧 Bot |
| 员工会话类型 | 群 / 频道（默认），或私聊 |
| 员工群 / 频道 / 用户 ID | 第 3 步找到的 ID |
| 接管关键词 | 触发转人工的词，例如 `转人工`、`人工客服`。消息**包含**任意一个即触发 |
| 区分大小写 | 默认否 |
| 接管时长（分钟） | 用户最后一次发言后多久自动结束接管，默认 60，用户每发一条重新计时 |
| 平台回复时限（小时） | 用户最后一次发言后超过多久不再允许员工回复。默认 0（不限）。**微信公众号、企业微信客服请填 48** |
| 转发接管期间的后续消息 | 默认开启 |
| 给员工发送用户详情 | 默认开启 |
| 用户详情中的最近对话条数 | 默认 10，最多 50；0 表示只发基本信息 |
| 进入人工时发给用户的提示 | 默认「已为您转接人工客服，请稍候，客服会在这里回复您。」，留空不发 |
| 退出人工时发给用户的提示 | 默认「人工客服已结束本次服务，后续将由 AI 助手继续为您解答。」，留空不发 |

### 第 6 步：把「员工回复处理器」挂到员工侧 Bot 上

员工的回复由插件里的「员工回复处理器」发回给用户，**必须单独挂到员工侧 Bot 上**：

1. 在 LangBot 创建一份插件处理器配置，选择 **员工回复处理器 / Staff reply processor**（无需填参数）并保存。
2. 打开员工侧 Bot 的详情页，在「**插件处理器**」板块点「添加插件处理器」，选刚才那份配置。

> 漏了这一步的表现：能转人工、员工能收到通知，但员工回复和 `!close` 都没反应。

### 第 7 步：测试

1. 客户侧发「转人工」→ 收到进入提示，员工群收到请求和用户详情。
2. 客户侧再发一句 → 员工群收到转发。
3. 员工回复（引用）其中任意一条（Slack 中在 thread 里回复，**不要 @机器人**）→ 用户收到，出现 ✅。
4. 员工回复 `!close` → 用户收到结束提示；再发消息，AI 正常回复。

## 员工日常使用

- **一定要回复（引用）转来的消息**，直接发在群里的普通消息不会转给用户。
- **回复时不要 @机器人**。如果员工侧 Bot 还配置了「群里 @ 就由 AI 回复」，@ 会多触发一条 AI 回复。员工群只做客服的话，可以关掉员工侧 Bot 的这条路由。
- 只支持**文字**回复，图片、文件不会转发。
- 发 `!close` 结束接管；不发的话，到「接管时长」后自动结束。
- 每条回复都有回执：✅ 已送达，❌ 会说明原因。

## 常见问题

**用户只看到「AI正在思考中，请发送任意内容获取回复。」**
这是微信公众号 Bot 的「加载提示语」，按第 1 步清空即可。

**员工回复了，用户没收到，也没有 ✅/❌**
「员工回复处理器」没挂到员工侧 Bot 上（第 6 步）；或者员工没有用「回复 / 引用」；或者员工侧 Bot 收不到群消息（Slack 检查事件订阅和是否在频道里）。

**员工群没收到请求**
检查插件权限是否已确认、群 ID 是否正确、机器人是否在群里。若员工侧平台不在支持列表内，插件拿不到消息 ID，无法转接（AI 会照常回复）。

**❌ 和 errcode（微信公众号）**

| errcode | 含义 |
| --- | --- |
| `45015` | 超过 48 小时回复窗口，需等用户再次发消息 |
| `45047` | 客服消息条数超限 |
| `43004` | 用户未关注公众号 |
| `48001` | 公众号没有客服消息接口权限，检查认证 |

**修改员工所在 Bot 或群 ID 之后**
进行中的接管会在用户下一次发消息时结束，用户需要再次触发关键词。

## 限制与说明

- 员工侧目前支持 Slack、飞书、QQ（OneBot v11）；其他平台需要先支持「返回消息 ID」和「引用回复」。
- 只处理客户的**私聊**消息。
- 插件不排队、不自动重发；发送失败以 ❌ 回执为准。
- 用户详情里的对话来自 LangBot 的消息记录，会发到员工侧平台，请确认符合你们的数据管理要求；不需要时可以关闭或把条数设为 0。
- 插件只保存「用户 ↔ 员工消息」的对应关系，不保存聊天记录。

## 从「公众号 Slack 桥接（OASlackBridge）」迁移

本插件是 OASlackBridge 的通用版，插件 ID 不同，需要重新安装和配置：公众号 Bot 对应「客户所在 Bot」，Slack Bot 对应「员工所在 Bot」，频道 ID 对应「员工群 / 频道 ID」，并把「平台回复时限」设为 48；最后把「员工回复处理器」挂到 Slack Bot 上，替换原来的「Slack 回复处理器」。旧插件中进行中的接管不会迁移。

## 给开发者

客户侧是一个 EventListener（`components/event_listener/handoff.py`，在流水线中运行），员工侧是一个声明 `usages: [event]` 的 Runner（`components/runner/staff_reply.py`，作为插件处理器订阅员工侧 Bot 的 `message.received`）。只使用标准的 `send_message`（返回 `message_id`）和入站 `Quote` 实现路由；Slack 文本转义只在员工侧 Bot 为 Slack 时启用。

```bash
uv venv
uv pip install -r requirements-dev.txt
uv run pytest -q
uv run ruff check .
```
