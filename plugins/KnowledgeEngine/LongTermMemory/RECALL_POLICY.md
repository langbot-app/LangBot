# Recall policy

Both explicit `recall_memory` and KnowledgeEngine retrieval use the same bounded record selector. Pipeline automatic memory injection reaches that KnowledgeEngine; stable profile blocks are bounded separately.

- Backend result order is the primary relevance signal. Backend scores and distances are preserved for transport but are not compared on an assumed universal scale. Importance and explicit event recency are small secondary signals; an old recorded timestamp alone does not decay a stable or legacy fact.
- Exact IDs, speaker identity, tags, and literal content matches can boost a result. This is not a semantic relevance classifier, and no universal similarity threshold or semantic abstention guarantee is claimed.
- Current recall honors `[valid_from, valid_until)`. Missing validity fields keep legacy records eligible. Explicit malformed bounds fail closed for current recall. Hidden lifecycle status queries and explicit `time_after`/`time_before` bounds allow historical inspection.
- `time_after`/`time_before` retain their old meaning: recorded `timestamp`, not event time. Scope and identity equality filters are sent to the backend and rechecked locally. String timestamps and string importance use local range checks, since Chroma range operators require numeric metadata.
- Retrieval considers a bounded window of 50–80 backend candidates and returns at most 20 complete records. Local time/status filtering may therefore return fewer results even when eligible records exist beyond that window. Exhaustive historical inspection remains available through the management/export paths.
- Repeated records with the same content, speaker, and time are collapsed. Different actors or event times remain distinct. Similar wording only receives a small diversity penalty; it never marks a memory replaced or deleted. A selected consolidation summary and its source records do not consume the same result budget twice. An overlapping summary is skipped as a whole, so selection does not guarantee coverage of every source represented in that summary.
- Complete serialized record candidates share an 8,000-character budget. Tool profile blocks each have a 2,000-character serialized budget. Oversized records/blocks are omitted, never sliced into partial facts or invalid JSON. Tool responses report omitted profile blocks in `profiles_omitted_for_budget`. The raw-record budget is conservative: it includes backend metadata that may not appear in the rendered answer. These are deterministic character limits, not exact tokenizer accounting.

The deterministic regressions cover scope and time boundaries, score-scale invariance, retention of old preferences, secondary importance/recency signals, distinct speakers/events, complete-record budgets, and summary/source diversity. They do not replace real-model extraction or answer-quality evaluation.
